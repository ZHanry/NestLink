# 原生中继会话的有界恢复

`Sdk::recover_native_relay` 持有一代已证明的 `NativeSession`。应用可以继续使用该代的发送句柄和已独占的业务接收器；恢复入口独立观察空闲停止，无须靠画面接收轮询触发。该入口完成一次恢复，返回拥有新端点和新会话的 `RecoveredNativeSession`。应用必须为新代次重新附加媒体、输入、文件与剪贴板的资源，不重放旧队列或旧输入。

本地终态区分 `TransportLost`、`ProtocolViolation`、授权撤销、到期、网络变化、平台变化、休眠、时钟异常和显式退出。只有传输丢失或网络变化、平台清理成功且原单调期限仍有效时，才能申请重连。已停止的会话不会变为活动状态；重连始终需要控制中心复查和双方签名。新的本地退出/撤销或任一控制观察器关闭会立即取消证明交换、DNS、连接与原生证明，关闭已拥有的传输。

旧会话提供当前最新续租许可及原单调截止时间，恢复入口保留二者。控制侧的 attempt 和被控证明协调都采用原截止时间与原墙钟到期时间的较小预算。旧会话清理、HTTP 重试、候选连接、SDK 结果复用和原生授权不能重新开始预算。`NativeConnection::authorize` 将端点最早期限进一步压入 `Session`；后续合法续租仍须新的已签名授权。

恢复配置包含明确选定的节点 ID、当前系统网络监视器、独立本地权限、路径和能力限制，以及退出/停止观察器。路径交集必须允许中继；未知必选能力、权限不足或对端公钥不匹配在新授权提交前拒绝。恢复先交换精确双方证明，再获取当前签名节点发现、申请新分配并固定解析地址。该入口只恢复明确选定的中继节点，QUIC 数据报与 WSS 在同一候选竞速中选择；它不替代初始多节点调度或 `direct_preferred` 的直连发现流程。

双方从同一交换中的旧完整许可摘要、32 字节随机 nonce 和节点 ID 派生一个 UUIDv8。输入使用独立 `NestLink/v15/reconnection-allocation/v1\0` 域，SHA256 的前 128 位设置 UUID 版本和变体位。该 ID 只用于协调和幂等；没有授权能力。不同交换或节点产生新 ID，响应丢失可重复请求同一预留，已关闭/过期的 UUID 不能复活。旧承诺容量仍保留至原期限。

主控先申请到最后一个名额时，被控仍可发现同一当前许可下已有有效分配的节点。签名发现同时检查完整会话绑定、控制运行、安全/连接/策略/配额代次、节点公钥/运行及地址代次，期限不超过已有分配。关闭、过期、旧代次或地址撤回不能用这条路径重新出现。节点描述不是容量承诺，额外 UUID 仍由原容量事务拒绝。

原生 QUIC 的应用关闭码 `0x4e01` 仅表示可申请替换传输，不是授权；普通显式关闭仍为终态。外层 QUIC/虚拟 UDP 将实际接收错误发布给会话监督器，再关闭内层，防止外层拆除掩盖原因。新增流、保留流额外数据和非法数据报为协议错误。WSS 字节桥保留实际协议错误，不能把错误降为普通 EOF；无关闭握手的断链仍作为传输丢失，TLS/协议错误保持终态。

开发回归包括实际回环 WSS 和外层/内层 QUIC：只改变主控网络事实，空闲被控从真实关闭获知失败，双方自动获取新许可、新分配、新端点和原生证明并传输双向合成业务帧；连续两次恢复、旧句柄拒绝、退出取消、被控等候证明时取消、平台清理失败、恶意载荷及满额配对另有验证。Windows 默认栈上的恢复异步状态采用边界堆分配，不以加大测试线程栈替代修复。

该范围尚未接入完整已安装 UI/daemon，也不证明真实公司/手机跨网、WSS 黑洞探测、浏览器 WebRTC/TURN、多节点故障转移、签名关闭回执、聚合配额、72 小时或 G0–G6/A01–A21 正式验收。
