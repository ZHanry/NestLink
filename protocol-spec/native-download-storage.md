# 原生文件下载的本地存储

`nestlink-platform-files::download::LocalDownload` 是同步磁盘适配，不解析网络消息、选择远程路径或签发业务权限。应用先在本机选择可信父目录中的一个全新私有下载区、一个本地文件名及大小上限，再传入真实 `FileReadClient::open` 获得的 `FileDownload`。本地名称只允许一个已经通过 portable path 校验的组件，不从对端文件名自动生成保存路径；既有目录不能冒充新的私有下载区。

下载区使用现有第一方平台安全边界创建：Unix 新目录 0700、新暂存文件 0600，Windows 使用受保护的 owner/SYSTEM DACL。后续 I/O 全部相对已打开目录句柄执行。Windows 的原读写暂存句柄只共享读取，其他写入、删除和重命名被 OS 拒绝；Unix 根路径被替换后仍使用原目录对象。信任边界是本机应用及同一 OS 用户的可信私有父目录；本适配不承诺防止同一 OS 身份任意修改其已拥有的文件。

`FileDownloadBinding` 是一个不透明的本地绑定，匹配实际客户端 owner 和传输 UUID。不同已证明客户端即使使用同一个 UUID、长度和摘要，也不能自动成为原下载。每次 `write_chunk` 同时核对精确绑定、客户端已确认偏移、暂存实际对象/长度、块几何/摘要、本地同意以及调用方提供的当前业务授权检查。一次只接受一块；磁盘写入失败保留 poisoned 状态，不把半写入当作已确认偏移。

`FileDownload::finished()` 原有含义是已关闭，也包含取消或失败。新增 `source_verified()` 仅在客户端收到匹配的完整 `End` 后成立；取消的源不能用于发布文件。`finish` 必须同时持有确切绑定的源完成事实、完整已确认本地长度以及当前同意/业务授权，再从原磁盘句柄分块重读全部内容，核对完整 SHA256，检查内存验证器并实际同步文件数据。

完成时使用同文件系统的原子 hard link 创建最终名称。目标已经存在为普通文件、硬链接、符号链接或目录时均拒绝，不覆盖、跟随或删除它。未完成的数据只有私有暂存名称。成功后关闭原句柄并删除自身暂存名称；Unix 另通过原目录能力打开一个可同步的读目录句柄并实际 `fsync`。cap-std 的原能力句柄可能是 `O_PATH`，不能直接当作可同步 FD。Windows 不声称已经完成目录同步或断电持久性验收。

`resume` 是一个明确的本地操作：新源必须已经证明，长度/完整摘要必须保持原值，起点必须等于实际确认的本地偏移。适配从原句柄重读实际前缀，与之前已确认字节的摘要比较，并重新建立验证器；错误前缀、源身份变化或偷偷追加内容不能被接受。新源的后续字节仍逐块检查，完成时仍重读实际完整文件。

本地 `LocalDownloadConsent` 显式撤销或 owner 析构都永久失效。平台调用前后、每次分块读取前后检查授权；源完成事实不代替当前会话授权。已发出的 OS 调用可能阻塞或在撤销后返回，已授权且已经落盘的字节不能收回。`LocalDownloadStatus` 保留确认偏移、实际发布、句柄关闭、暂存清理、目录同步和 poisoned 事实；后续检查/清理失败不会把已发布文件改称为从未写入。`cancel` 只清理自己生成的暂存文件，永不删除最终目标。析构只关闭句柄，不虚构暂存文件已清理。

这些同步 API 不得在 Tokio 执行器或业务授权锁内运行。现已接入 [owned 下载目的端线程](native-download-worker.md) 和 [原生 SDK 流程](native-sdk-files.md)，通过 `LocalDownloadSelection` 把初始化、读写、发布和清理都放在原线程中，支持已确认屏障后的同范围接续与真实迟到结果监控。这里的同步函数没有声称有界的 OS 清理完成时间；既有保存目录的安全导出、daemon/GUI 产品流程、上传、Android SAF、浏览器存储及跨网/安装/断电验收继续实施。
