# 原生文件读取与校验续传

`NativeFileRead` 的 `FileRootsRequest` / `FileRoots` 动作在 FileRead 通道上
返回最多 `FILE_READ_ROOTS` 个当前获批根目录标签。列表是单页、按 root ID
排序，仅含 root ID 与本机选择器提供的 `display_name`，不含 native path。
独立目录元数据同意在处理请求时检查，并在响应排队后实际写入前再次检查；
撤销任一已列出的根会阻止此前构造的列表泄漏。

`NativeFileRead` 使用已完成端点证明的 `FileRead` 可靠通道。它需要当前会话的 `FileRead` 权限；主控和被控分别拥有自己的 `FileReadClient` / `FileReadServer`。连接代次绑定消息，严格递增请求序号匹配原请求的传输 UUID，迟到响应不能回答新请求。取消一个尚未收到完整响应的客户端 future 后，原客户端不能发送替代请求；再次使用会明确终止会话。

本机先明确选择目录并获得 `ApprovedReadRoot` 和独立 `ReadRootConsent`。目录 ID 是定位标识，没有独立权限；本机批准只交给该会话的 provider。远端只能提交目录 ID 和相对路径，不能传入任意绝对路径。未配置目录时没有文件读取能力。本地私有下载区及原子发布另见 [native-download-storage.md](native-download-storage.md)，原生 SDK 见 [native-sdk-files.md](native-sdk-files.md)。本机目录元数据基础见 [native-directory-storage.md](native-directory-storage.md)；网络目录浏览、上传、Android SAF、完整应用目录批准/展示流程和浏览器文件产品入口仍未完成。

## 路径与本地对象

相对路径是保留原 UTF-8 字节的 `/` 分隔名称，最多 4096 字节、32 层，每层最多 255 字节。不进行解码、规范化或修补。空层、`.`、`..`、绝对/UNC/盘符路径、反斜线、ADS、控制字符、Windows 设备名称、尾随点/空格和通配字符拒绝。

`nestlink-platform-files` 通过固定版本的 Bytecode Alliance `cap-std` / `cap-fs-ext` 实现句柄相对查找。根目录仅在本机批准时使用 ambient authority；每个子目录是一个单独的 no-follow 组件，最后的文件同样 no-follow。不会先 canonicalize 再按绝对路径重新打开。不同文件系统、非普通文件、硬链接数不为一及 Windows reparse 文件拒绝。Unix 打开使用 NONBLOCK，在类型检查前 FIFO 不会等候写入端。Windows 文件句柄只共享读取，阻止其他写入/删除/重命名；根句柄也会阻止目录路径被替换。Linux 即使根路径被重命名并替换，仍读取原批准目录的对象。批准是对已打开的对象，局部本机重命名不会重新选择 ambient 路径。

本地目录同意可以独立撤销，析构其本机 owner 同样撤销。工作线程每 50 ms 检查纯本地同意事实，退役空闲源文件与根句柄；随后请求和精确重试都返回拒绝。缓存的文件块没有撤销例外。目录撤销只结束对应文件传输，已批准的观看仍可继续。磁盘调用若已阻塞，只能在其返回后关闭拥有的句柄；其迟到结果不会进入已停止会话。

## 请求和完整性

`Open` 包含目录 ID、相对路径、读取起点和可选的完整 SHA256。非零起点必须指定完整 SHA256。工作线程从实际打开的文件取得长度/标识/修改时间，分块计算完整内容摘要，并在每块前后复查本地同意和当前会话。长度不超过本机配置及协议 1 TiB 上限；这不是对所有大小的产品性能承诺。摘要或起点不匹配返回 `FILE_READ_CHECKSUM_MISMATCH`，不继续读取。

`Next` 只能请求上次已确认的精确偏移。每块数据最多 61440 字节，包含偏移和块 SHA256；整个 Protobuf 封包连同元数据不超过原 FileRead 65536 字节预算。客户端复查响应代次、序号、传输 ID、动作、长度、偏移和块摘要，身份或内容替换为协议错误。一次只拉取一块提供背压，不提前读完整文件进内存。

到末尾还要从原句柄重新验证完整内容及元数据，关闭源文件后才返回 `End`。Unix 文件可能被其他本地进程写入；即使其恢复原长度和修改时间，最终内容验证也拒绝不同内容。客户端的 `FileReadVerifier` 必须校验实际收到的完整字节。续传时首先分块输入实际本地前缀，再校验新块，最终 SHA256 必须匹配原完整摘要；错误前缀不能因为远端接受起点而算成功。`LocalDownload` 另重读实际磁盘前缀/完整文件并原子发布，调用方不得在验证与实际保存完成之前宣称下载成功。

相同最新请求的解码字段原样重试，只返回原缓存结果，不重复读取或推进偏移；缓存仍核对当前会话及本地目录同意。改动的重试、跳号、错序、已关闭 UUID 重新打开或错误代次终止会话。取消、失败和成功均保留本运行的 UUID 墓碑。最多四个活动源、256 个传输记录、16 个批准根；超过上限返回容量错误，不能靠取消增长无界表。错误只暴露固定的文件错误枚举，不返回 OS 绝对路径或原始错误内容。

## 生命周期和实际验证范围

每个服务只有一个独立磁盘线程和一个有界工作槽。读盘、完整摘要和元数据调用均在授权锁与 Tokio 执行器之外；授权检查仅在短临界区发生。空闲/背压/阻塞磁盘期间，会话监督仍可处理撤销、租约、网络和退出。已经交付给合法调用方的字节无法收回；停止后不会新交付迟到块。QUIC 的独立流保持文件与输入/媒体分开；TLS/WSS 共用可靠字节流仍有线上的队头阻塞，不声明延迟保证。

单个请求还有固定 30 秒操作预算，并且受到原会话许可的更早期限约束；合法续租由原会话机制执行，文件重试不续租。服务/客户端拥有独占 FileRead 消费者，整个拥有者析构遵循当前原生通道规则，停止整代会话。显式 `shutdown` 最多等待 250 ms，返回 `Finished` 或 `TimedOut`；monitor 的超时事实保持，即使线程后来完成。monitor 只有在 provider、所有源及缓存已经析构后标记 `finished`，不会把尚在阻塞的文件系统调用称为已清理。

客户端另有文件级显式 `retire(self)`：只有已消费确切请求回执、并且每个成功打开的源已消费 `End`、`Cancelled` 或 `Failure` 才能退休。单纯析构本地 `FileDownload` 不满足远端源清理。退休永久保留 incoming FileRead claim、清空原队列并丢弃该通道的后续帧，既不交给 fallback 也不因无人消费而阻塞 TLS/WSS 的其他通道；仍按当前权限检查入站帧。其他通道消费者的默认析构停止规则不变。退休后的 claim 不能重新打开，同连接下一下载应复用仍 idle 的原客户端；SDK 的返回 guard 实现这一流程。退休前验证失败会结束错误使用的原会话，不伪造源已关闭。

开发测试使用真实私有临时目录、Windows junction、Unix symlink/FIFO、硬链接、根路径替换、固定文件句柄与本地同意撤销；实际回环直接 TLS/QUIC 完成持钥证明并读取/校验多块文件、空文件和续传。错误前缀、持有正确 TLS 密钥但替换响应/块摘要、精确/变造重试、活动和墓碑上限另有验证。阻塞磁盘替身验证独立输入队列与两秒内撤销，同时保留真实未完成清理状态，不操作宿主文件、输入或桌面。本批完整检查与固定源码见开发检查点；这些测试不替代 WSS/跨网产品下载、完整 UI、Android/Web、安装包、磁盘满/异常存储性能或 G0–G6/A01–A21 验收。
