# Run two-relay business sessions through the existing SDK owner

Status: source implementation; new SDK tests await GitHub Actions.

The complete ordered NRD2 credentials now enter the existing SDK route adapter
through `RemoteChainAuthority` and `authorize_remote_chain`. The adapter delegates
network admission to `RouteAuthorization::remote_chain` and retains the same
SessionSetup, independent SessionPermit, mutual endpoint proof, signed lifetime
cap, bounded channels, synchronous revocation and physical cleanup owners.

A separate NRD2 business runtime would duplicate authorization and cleanup. A
single-hop adapter supplied with only one TransitGrant would omit the second
node's authority. The small authority discriminator reuses the established path
while requiring both original transits in their canonical order.

Two source scenarios create four logical nodes and three actual mutually pinned
outer QUIC adjacencies. Both canonical controller/host orders prove the original
business permit, reject unapproved input, and read a 98,335-byte approved OS file
through the production FileRead server, client and manifest/chunk verifier. They
then stop both business sessions, revoke both forwarding owners and rebind all
six original UDP addresses. The strict Actions source inventory now includes the
nested chain module and still requires exact equality and zero failed/ignored
tests. No local test or formatter was run.

These are business-over-carrier component scenarios. Registered production
NRD2 node listeners/dialers, management chain selection and continuous observed
adjacency reporting remain required. This slice does not complete W12, qualify
AC18/AC19, or make the release ready.
