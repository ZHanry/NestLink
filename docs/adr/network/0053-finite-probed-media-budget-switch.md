# 已实测签名媒体预算之间的切换

状态：生产接线已提交，待精确源码 Windows/Linux 托管验证。W31/AC53 整体未完成。

比较直接修改不可变 execution target 的码率与复用现有离散 FormatSet、
VideoQuality、实际 Media Foundation owner、sealed AU、格式提案和 ACK。
选择后者；前者会使原签名摘要与实际编码器配置不一致。
不增加拥塞控制器，Quinn、原优先级队列和已有观测控制仍承担原职责。

显式 CPU 产品目标作为上限。最多增加两个相同像素尺寸的帧率/码率预算，
分别为上限的 3/4 与 1/2，帧率最低保留 min(上限,15)，码率最低 64kbps。
去除重复预算。每个候选分别执行原完整编码或解码方向探测，检查实际输出、
SPS、几何、flush 和 close 后才进入同一个历史公告；不根据上限推导可执行能力。
公告的 probe resource_id 标识该串行批次的第一个已关闭历史 owner，
每个格式的能力来自批次内各自的实际 owner；它不是任何 live execution 的身份。
原单 worker、取消、30 秒期限、失败隔离和缓存原到期时间不变。

发送端复用 VideoQuality 预算，在当前已批准几何/色彩/编码族内选择完整离散格式。
没有足够低的已批准格式时停留在最低已批准预算，不生成未探测格式。
升档仍要求原连续健康窗口，未知接收反馈不能提供升档资格。
切换前 checked close/join 原编码器，清除其有界在途映射，再启动新精确 target。
只有新 owner 的实际 sealed AU 能登记 execution，原 proposal/ACK gate 暂停数据直至确认。
设备/会话/源变化、撤销和原 lease 均保留，旧 receipt 不得向新 owner 提交数据。

Windows 正向回归将逐项实测三个预算，真实高档编码/解码后切换至签名低档，
在途 ACK 被原 barrier 暂扣时仍不得发送，释放后要求实际低档像素输出，
并验证双方旧执行代次回收及旧 receipt 拒绝。
这不能替代真实20到5Mbps/1%丢包、文件/输入并发或两秒/原p95门槛。
分辨率缩放需要可复用的实际缩放 owner、输入坐标映射及独立格式实测，仍为必需后续工作。
