# ADR 0078: Give original full Rust checks independent hosted job budgets

Source 745c05a / run 41479911345 retained an actual Windows job timeout: GitHub reported the maximum execution time of one hour. The original workspace command began only after about 47m50s of native builds, focused runtime checks, strict lint and diagnostic artifact builds. Only about 12m13s remained. Linux separately finished its workspace command with an original resident test target failure. Neither result qualifies a full workflow pass.

The existing GitHub-hosted workflow is split into three independent Windows/Linux matrices: core keeps the original focused checks, lint and diagnostic builds; workspace runs the unchanged complete workspace and scoped renewal commands; boundary-tools runs the unchanged sanitizer, Node, Python, UI token and xtask commands. Each reuses the original pinned native input preparation and ordinary Windows token setup. Every job keeps the original 60-minute ceiling and debug assertion settings. No case, assertion, default workspace test parallelism, test timeout, permission or supported platform is removed. All jobs must succeed for the required workflow to succeed.

The alternative of increasing the original job timeout would conceal the scheduling constraint without separating independent evidence. Moving only the workspace to an optional workflow could leave the required source without complete coverage. Independent required jobs preserve the full check set and make failures attributable to each actual command. Rebuilding pinned inputs on each hosted job costs additional runner time; no user computer is a build runner.

This scheduling change does not fix or reclassify the original Linux resident failure. Its real desktop fixture isolation is reviewed separately in ADR 0077. Existing failed and cancelled run evidence is retained, and the new workflow is unverified until exact-source Actions execution. Local edits and manual diff review are not a workflow pass.
