# 原生接收端观测接入既有媒体 producer

状态：生产接线待精确源码 Actions 验证；不代表 W31 或目标设备验收完成。

比较仅使用本地 enqueue/编码耗时与复用现有已认证 VideoFeedback 通道传递接收观测。
选择后者补充既有 VideoQuality，不另造拥塞控制器；Quinn 及原通道队列继续承担传输拥塞与背压。
`native-receiver-qos-v1` 仅在双方原生设备均声明支持时加入原有签名 permit，浏览器仍使用原 WebRTC 反馈。
未协商该能力的会话维持原控制逻辑。该能力不会授予新的 View/Input、显示源、格式或会话权限。

报告每个已批准源在约 500ms 窗口内收到的 payload 字节数、帧数、最后媒体序号，
以及可观测 CPU 解码次数和最大解码耗时。异步外部 decoder 的解码结果明确为空；
这些字段均不表示实际呈现、输入到显示延迟、网络丢包率或可用带宽。
报告有版本 magic、严格规范编码、有界长度和原会话/布局/源/格式绑定。
接收窗口及 producer 历史最多各 64 个源，使用现有反馈有界队列，满队列丢弃报告且不消费报告序号。
多源各自采样，单会话报告序号连续；旧布局或格式的在途报告只消费序号，不刷新当前健康状态。
相同报告的重传不刷新时钟，未发送帧的确认、倒退序号、跨代次和不一致上下文拒绝。

既有 producer 在接收积压或解码明显跟不上时降低预算，忽略过期观测的升级资格。
计算积压时扣除报告到达后按当前 fps 正常生产的帧，避免把报告采样周期误判成拥塞。
连续健康窗口、原批准上限、关键帧/源/格式 ACK、撤销、原 lease、清理语义保留。
当前动态精确格式 producer 只接受报告，仍需通过原格式 owner 完成预算或分辨率切换，
不能通过修改格式摘要或跳过协商把观测当作新格式授权。

验证覆盖规范消息反例、未知观测不升级、多源/采样周期、重放/旧布局与实际 VP8 编解码，
实际反馈通过原 TLS/QUIC 双向通道并随原 lease 撤销停止。
