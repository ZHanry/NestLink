# 显式内部软件候选的有限精确格式

状态：源码实现，待同源 Actions 验证；不构成完整 W31、GPU 或发布资格。

审查发现 CPU provider 新增三档实际探针后，原内部候选政策只允许单格式公告，
会使已有显式候选配置拒绝自身的公告。保留旧私有 JSON 的单格式语义：省略
`additional_formats` 时仍只探测并公告原 `format`，不隐式扩展批准范围。

比较从主格式自动推导允许范围与显式列出完整精确格式，选择后者。私有配置可增加
最多两个 `additional_formats`，每项都是实际观测的 canonical VideoFormat 字节。
原 `format` 和 `format_sha256` 保留为显式最大目标。附加目标必须是同编码族、
profile、色度、位深和色彩；宽高、整数帧率和码率不高于主目标，且长宽比相同。
重复、错误几何、增大目标和多于三项均拒绝。每档仍需独立实际 encode/decode，
配置自身不能证明该档可执行。

服务端签发、真实 HTTP 首次批准和续租、本机候选配置、方向公告和 Session 激活
复用原授权边界，必须匹配同一个完整排序后集合和原集合摘要。缺少一档也失败，
不允许交集缩小后静默改变已审查候选。两个端点和服务端需配置相同完整集合。
provider 只探测显式集合，不把另一个 convenience ladder 混入历史公告。

默认生产签发开关和所有硬件、现场、性能及发布门槛保持原要求。新增测试分别
覆盖旧 JSON 兼容、有限集合的反例、本机 provider 目标和两种真实 HTTP 授权流程。
媒体 owner、首 AU、精确格式 ACK、原显示源和输入坐标仍由原运行时管理。

Windows 实际 MF / Core 回归在检查默认激活拒绝后，使用两端真实三档方向公告
配置精确内部政策，经普通 `Session::activate` 完成正向媒体及降分辨率验证。
debug feature 仍只用于夹具装配；该用例没有使用调试激活方法放行正向业务。
HTTP 签发测试是独立授权验证，不冒充同一次端到端拨号或真实桌面性能。
