# 0.5.0 RC 跨网络连接与会话功能

公司连接家里时，直连可能被公司 UDP 策略、家庭 NAT 或运营商 NAT 阻止。0.5.0 RC 在自动模式中保留直连和已授权中继路径，直连受阻可使用管理服务器的 WebSocket 字节中继。中继内部仍由双方完成 TLS 身份校验、会话证明和逐通道授权。

## 首次配置

1. 将管理服务器和两端客户端同时升级到 `0.5.0-rc.1`，连接同一个 HTTPS 管理地址并登录。桌面端登录后自动登记本机；已有安装身份保持不变，登记失败可在远控页重试。
2. 管理员在“网络策略”中把服务器转发设为 `allow`，远控路径设为 `direct_preferred`。初始部署默认 `deny/direct_only/disabled`；仅升级不会自动扩大权限。“公网服务入口”不影响原生远控中继，可继续关闭。
3. 检查账号、双方设备及会话的路径限制，确保均允许 relay。策略按各层限制求交；任何一层禁止中继都会使中继不可用。修改策略后重新申请会话。
4. 管理地址前的 HTTPS 反向代理须支持 `/api/v3/remote/*/relay` WebSocket Upgrade，保留长连接且不要缓存。现有 Caddy 模板支持 WebSocket；也需检查公司代理允许到此 HTTPS 地址的 WebSocket。
5. 被控端保持登录，允许程序在托盘运行。控制端选择设备和所需权限，点击“连接设备”；被控端明确批准后会自动继续建立会话。已有受信设备或固定密码授权仍受其当前权限、路径及有效期限制。

自动模式可尝试独立数据节点及管理服务器中继；无需为基本原生回退另外部署数据节点。浏览器 WebRTC 仍使用其独立的 ICE/TURN 路径，管理服务器字节中继不替代 TURN。公网服务发布与远程控制分别授权。

## 浏览器跨网络配置

0.5.0 RC 将服务器的 `native_stun_servers` 发现配置同时接入浏览器和原生 WebRTC 宿主。配置只从已校验的管理通道读取，不使用对端指定的 ICE 服务器。直连模式收集本机及 STUN 反射候选；自动模式在获准时加入受管 TURN，仅中继模式只使用 TURN。更新或撤回可选 TURN 凭据不会清空 STUN。

管理员应确认配置中的 UDP STUN 地址从两端均可达。STUN 能发现 NAT 映射，但不能穿透所有 NAT 或公司 UDP 限制；这类部署还需注册可用的浏览器 TURN 节点，并为账号、双方设备及本次会话允许中继。默认 `deny/direct_only/disabled` 和零 TURN 节点的部署，仅更新客户端仍无法覆盖所有跨网络场景。请参考[服务端配置](refactor/SERVER.md)。

本次故障的分析材料显示：管理信令和屏幕批准成功，SDP 只有私网或 mDNS 本机候选，没有 `srflx` 或 `relay`；随后在 ICE 建链阶段耗尽启动许可。修复补齐发现配置，并将这类失败显示为 ICE 建链超时；不延长已签署许可，也不跳过双方身份校验。

## 多端登录与被控提示

每次登录建立独立管理会话。桌面和 Web 在访问凭据到期前自动续期；临时网络错误保留当前有效登录并重试。普通权限拒绝不会退出账号。退出只撤销当前登录；修改密码等账号安全操作仍可撤销全部登录。

被控桌面在当前屏幕右下角显示独立置顶提示，主窗口收进托盘后继续显示。待审批时可以查看并批准或拒绝；准备和共享期间可以断开。提示包含远端设备、权限、路径与共享时长；屏幕选择仍需本机明确批准。

## 常用会话功能

浏览器远控在访问获批后，会提示被控端选择并批准屏幕。守护进程自动准备宿主，不需要再点一次启动。屏幕批准完成后才标记就绪，浏览器随后领取新的 15 秒会话许可、提交 offer，双方身份核验后开始捕获。服务器、Web 和被控端应一起升级；旧服务器没有新的就绪接口。

| 功能 | 使用与授权 |
| --- | --- |
| 设备管理 | 搜索名称或 ID、选择设备，登记或撤销本机身份。已登记不代表实时在线。 |
| 键鼠 | 连接前选择“远程控制”，被控端授予输入权限；停止、失焦或撤销时释放输入。系统权限边界仍由操作系统及可选权限代理控制。 |
| 文件 | 分别批准读取/写入文件。被控端选择共享目录，控制端在文件面板选择、上传或下载；目录边界和配额继续生效。 |
| 文本剪贴板 | 分别授予读取/写入剪贴板，按面板操作同步；不会以连接成功替代剪贴板授权。 |
| 多屏 | 被控端授权可捕获屏幕，控制端在会话中选择可用显示器；显示器变化后需刷新并重新确认授权范围。 |
| 音频 | 连接前请求音频权限，获准后守护进程自动接入本机系统音频设备，使用 Opus。Windows 使用系统默认设备；Linux 使用本机配置的 PipeWire endpoint。会话工具显示授权范围。 |

## 连接失败排查

- 一直等待批准：确认选中的是家里电脑的当前设备身份，被控端已登录同一部署、可以访问服务器且请求未过期。双方均需升级到支持自动接续接口的客户端。
- 一直等待屏幕：在被控端远控页确认共享屏幕；如果准备失败，查看连接诊断并重新申请。`browser-host-diagnostics.jsonl` 在私有状态目录保留最近最多 64 KiB 的阶段、错误分类和耗时；它不包含屏幕或凭据。
- 直连失败：自动模式需允许 relay；公司禁止 UDP 时可选择“仅中继”。仅直连模式不会绕过本地网络或设备限制。
- 浏览器 ICE 建链超时：检查服务端 STUN 的 UDP 可达性，以及是否有可用 TURN 节点和中继权限。原生 WSS 中继可用不代表浏览器 TURN 已配置。
- 中继失败：检查服务器转发策略、双方设备与会话路径、WSS 反向代理、服务器限额和账号登录状态。中继目的地址来自已核验的管理服务器，不采用对端任意指定的地址。
- 同局域网无法直连：私网 CIDR 仅由本机用户明确批准。需要时在“本机访问与网络设置”中添加实际局域网范围；服务器发现配置不能替本机授予私网拨号权限。
- 网络切换或睡眠后断开：原授权和旧网络候选失效，按会话恢复提示重新确认；不要反复使用过期许可。

自动化回归覆盖管理服务器 WSS 回退、批准后被控端接续、停止不复活、UDP 黑洞下 WSS 并发预算、输入清理期间的执行器调度及现有通道授权。真实公司/家庭公网、物理设备和 90 分钟持续会话验收仍需在实际部署执行；Release 的验收材料保留这些状态。
