# 0.5.0 RC 开发验证

## 故障结论与修复边界

跨网络分析材料中的信令、屏幕批准及 SDP 交换已成功，失败出现在 ICE 建链。管理服务器提供的 STUN 发现配置没有进入浏览器和原生 WebRTC，只有本机候选；部署同时没有 TURN 节点，并采用仅直连策略。0.5.0 将受信任 STUN 配置接入两端，保留 TURN 续期及回退时的 STUN 配置，并单独报告 ICE 超时。仍需部署可达 STUN；受限 NAT 或禁 UDP 网络需要允许中继及可用 TURN，不能用原生 WSS 代替。

服务端原本允许同账号的独立登录。桌面和 Web 缺少访问凭据自动续期，Web 还把普通 403 当成登录失效。客户端现按各自管理会话续期，临时失败保留有效登录并重试；退出仅结束当前登录。密码修改等账号安全操作仍可结束全部登录。

被控提示为右下角独立置顶窗口，覆盖待批准、准备、屏幕选择、共享及停止状态。主窗口隐藏后仍显示，可查看、拒绝或断开；所有动作继续核对当前核心代次、请求和连接代次。

## 本地开发检查（2026-10-19）

- 受影响的 app-core、desktop、web、sdk、storage、protocol 套件：524 项通过、1 项既有忽略；新增临时续期失败恢复测试另行通过。
- 新增真实服务端回归覆盖空闲自动续期、三个独立登录的续期和退出，以及修改密码撤销全部登录。
- STUN 回归覆盖 IPv4/IPv6 地址校验、TURN 容量不足后的直连回退、可选 TURN 撤回后保留 STUN、仅中继不启用 STUN。额外用本地 UDP STUN 响应器验证原生连接实际收集并在 SDP 发布 `srflx` 候选，保证配置在 ICE 收集器创建时生效；不依赖外网服务。
- `cargo clippy --workspace --all-targets --locked -- -D warnings`、WASM 编译、Web 生产构建及 `cargo xtask check` 通过。
- Python 仓库检查：217 项检查（19 项按平台或外部工具条件跳过）；更新发行说明后的 RC 发布器 36 项回归通过。
- 本地 Chrome、Edge 使用当前 Web 生产产物、真实管理服务和原生 AppCore，完成 WebRTC/VP8 画面、许可续租和停止清理。捕获源是自有合成像素，不采集真实用户桌面。
- Windows 实际渲染检查覆盖中文浅色共享提示、英文暗色来访提示、长权限文本，以及主窗口隐藏后继续显示。关闭提示窗口不会隐去共享状态。

这些开发检查不等于真实公司到家庭网络、物理安装或 90 分钟验收。候选发行的验收材料继续分别保留待验收状态及签名状态；不把本地回归推断为所有网络均已可达。
