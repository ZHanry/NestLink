# 0.7 remote workspace direction

The brief is Windows host, Edge controller and native Windows controller;
device selection and an authorized desktop session are the primary tasks.

Palette: action blue `#1467D5`, action text `#0D56B4`, canvas `#F4F6F9`,
navigation `#EBEFF5`, surface `#FFFFFF`, body `#172337`. System Segoe UI and
the installed Chinese UI fallback preserve native legibility. Body 15 px,
secondary 12 px, section 19 px and page title 28 px; names and actions align left.

```text
Navigation | Search / computer list | Selected device / access options
           | name, platform         | Enter desktop

Remote desktop: device and connection state       Control center / Fullscreen / End
                    approved screen occupies the remaining viewport
Control center: Displays | Files / clipboard | Connection and measured performance
```

Keep the remote screen dominant, put tools behind one explicit control-center
entry, and leave termination available. Blue communicates a selected device
and the next action. Device rows carry computer identity rather than a generic
grid of status cards. Use NestLink's own linked-N assets and outline icons.

Review against the brief: retain the existing three-part desktop workspace
instead of introducing a marketing hero or a statistics dashboard. The new
performance grid is confined to session tools and uses actual observations.
An absent metric says not observed; hardware, zero-copy, H.265 and true color
remain unavailable until their actual backend and negotiation prove them.

States to verify: no devices, search empty, selected device, pending approval,
screen consent, negotiation, picture waiting, connected, display switch,
network recovery, permission rejection, expired setup, revocation and cleanup.
Primary actions have visible focus; the tools remain usable with keyboard and
at narrow widths. A registered device is not described as online without a
presence signal. Export excludes credentials, SDP, addresses and remote data.
