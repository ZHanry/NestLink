# 原生安全恢复与远控窗口续接

状态：`implemented_unverified`。对应 F07/F23、W14/W30、AC21–AC23 与 AC67 的产品接线切片；本记录不表示这些工作包或真机验收全部完成。

## 用户行为

原生连接因网络变化或传输丢失而完成旧资源清理后，工作台、连接进度和原远控窗口显示“正在恢复连接”。内部恢复没有公共 operation ID，因此“停止恢复”按原请求及当前连接代次发送 `StopNativeSession`，不能依赖只适用于初次建连的 `Cancel { operation }`。

双方完成原安全恢复证明后，原控制窗口重新绑定新业务代次。窗口清除旧图像、统计、输入绑定及本地按键状态，并打开会话工具；显示器选择和启用控制继续要求新的明确操作。该接线复用原恢复、显示确认、输入释放、视频和 IPC 实现，不创建新的网络协议、重放缓存或媒体组件。

## 续接证明与边界

Core 新增可选快照字段 `recovery_chain_origin_generation`。初次或显式 `StartNativeSession` 均为 `None`。只有没有公共命令 envelope 的内部恢复，在原会话快照仍是对应请求、对应前序业务代次且已完成恢复前清理，同时新证明代次恰好为 `previous + 1` 并通过原身份、期限及取消栅栏时，才建立或继承该连续恢复链的最初代次。停止和失败快照保留已取得的链证明，供资源清理使用；它不授予任何业务权限。

窗口 owner 固定保存创建时观察到的 daemon runtime ID、Core 登录代次、请求 ID、最初观察的连接代次及链起点。后续快照必须具有完全相同的链起点，连接代次必须严格前进。若窗口暂停期间漏掉中间快照，可以接续同一链的后继；不能靠当前 target 的代次拼出新的链起点。换 daemon、换登录代次、换请求、换链起点、无证明的大代次或向后回退均不续接。离线会话保持其独立授权流程，不借此恢复在线权限。

画面续接还要求后继为无错误、无停止原因的 `Connected` 状态。恢复中、停止中或终态不会重新启用视频或输入。

## 关闭与并发

用户关闭窗口时，原代次的停止命令可能尚未到达 Actor，而新的安全后继已提交。清理流程仅使用原 owner 的链证明更新待清理代次，重新停止实际后继，并保留同一请求的原撤销操作。这个分支关闭视频和输入，不重新显示远控内容。旧代次延迟到达的停止回复不再拥有新清理槽。

窗口只有同时收到当前代次的成功资源清理、成功停止结果及请求终态/撤销结果后才关闭。单独的停止成功回复、单独的本地资源清理或单独的撤销回复都不能替代其余证据。

## 验证入口与剩余边界

- `apps/desktop/src/remote_recovery.rs`：固定 owner 的链验证、跨过两个代次、逐代续接、恢复后新开窗口、runtime/登录/请求/终态等反例。
- `apps/desktop/src/layout_tests.rs`：真实 egui 点击“停止恢复”发出精确原请求/代次；窗口清除旧输入和视频；恢复期间关闭恰逢后继提交；旧停止失败回复不能污染后继；只有当前清理及撤销终态完整后关闭。
- `crates/app-core/tests/native_recovery.rs`：原真实 server/SDK/Core/transport 恢复测试增加显式初始连接无链证明、第一次和第二次恢复继承同一起点的断言。
- `crates/app-core/tests/native_session/route_set.rs`：原真实节点全断场景的安全后继增加链证明断言。

新增验证必须由原 GitHub 托管 `rust-core.yml` 完整 workspace、原 `native_recovery` 和 `network-rewrite.yml` route-set 用例执行；源码格式由原 `network-source-format.yml` 生成补丁。此切片没有运行本地编译、格式化、lint、自动测试或应用。具体源码 SHA 与运行结果由主线程统一记录；尚未取得本次 exact SHA 的 Actions 结果。
