# 签名空间直连的原生远控恢复

当前候选源码在空间直连的原生远控发生网络变化或连接丢失后，先完成旧会话的输入、
媒体和物理连接清理，再由双方重新认证一个新的业务代次。恢复继续使用同一空间、
双方成员凭据和直连权限。初始路径授权最多 **30 秒**，恢复保留这次授权的原始期限；
原期限内最多允许 **16 次**安全恢复。到期、撤销、清理失败或达到恢复上限后停止，
需要按现有流程重新发起并批准远控。

本次新增源码、自动用例及兼容验证程序都待对应新 SHA 的 GitHub Actions 执行。
本文不表示真实跨网、Windows 目标设备或混合安装版本验收已经通过。

## 启用与日常使用

两端都使用包含此实现的版本，并由管理员通过已有空间管理流程将双方设备加入同一
空间、签发各自当前成员凭据。核对部署 ID、空间 ID 和管理员通过可信渠道提供的
空间签名公钥。远控请求仍需独立批准屏幕、键鼠等业务权限及直连路径；空间成员
资格不能替代这次远控批准。私有地址仍需要两端已有的本机私网前缀批准。

桌面端在没有活动会话、建立、清理或恢复任务时，打开本机连接网络设置，选择
「使用空间授权，仅允许直连」，在两端填写相同作用域并重新确认本机批准：

| 字段 | 需要填写的内容 |
| --- | --- |
| 部署 ID | 当前受信管理部署的 UUID |
| 空间 ID | 双方设备所在空间的 UUID |
| 本机信任的空间公钥 | 管理员核对过的完整 32 字节公钥，界面使用无填充 base64url |
| 控制端成员凭据 ID | 当前控制端设备的成员凭据 UUID |
| 被控端成员凭据 ID | 当前被控端设备的成员凭据 UUID，与控制端不同 |

保存后正常发起并批准远控。连接丢失或网络变化时，界面可能暂时显示建立状态。
恢复后，被控端需要重新选择共享屏幕；新视频从新的关键帧开始，新输入绑定只在
当前代次生效。之前按下的按键会释放，旧画面、输入、音频、剪贴板写入、文件操作
和其他待发送业务不会自动重放。普通 TCP 连接的请求恢复不在本功能保证内。

这一路径始终仅直连。若当前网络无法完成直连、管理面拒绝、成员凭据失效、原始
路径或任一恢复祖先被撤销，就停止这次尝试。双中继模式有独立配置和一次恢复限制，
详见 [原始双节点组恢复](ORIGINAL-ROUTE-RECOVERY.md)。

## daemon 配置

使用私有 JSON 文件保存上表作用域。JSON 字段是 `deployment_id`、`space_id`、
`authority_key`、`controller_membership_grant_id` 和 `host_membership_grant_id`；
其中 `authority_key` 使用完整的 32 个 0–255 整数组成的数组。文件最大 8192 字节，
并须满足已有平台私有文件权限要求。配置来自可信本机操作，不能从对端信号填入。

```text
nestlink-daemon --native-space-path <私有JSON文件的绝对路径>
```

该参数通过校验后保存本机设置，后续启动省略它仍保留已经保存的配置。清除未来
会话的空间直连配置使用：

```text
nestlink-daemon --disable-native-space-path
```

显式保存空间直连配置会清除原双中继配置，反向亦然。清除空间配置后，后续会话
遵循原部署与 SessionPermit 的路径策略，操作前应核对该策略和本机批准。

## 丢失响应、撤销与期限

控制端为一次新代恢复只提交一个固定路径请求。即使服务端已提交但 HTTP 响应丢失，
客户端也只读取同一个请求派生的路径 ID，不以新的 ID 再分配。若实际请求失败或
原始路径已撤销，本次恢复终止；读取旧响应不能恢复已被撤销的权限。被控端短暂
等待控制端签发时，也不会获得业务权限或重启原授权期限。

新的业务代次、轮询、重新发现地址和恢复次数都不会延长原路径授权。最多 16 次是
额外的恢复次数上限，不代表每次都能获得新的 30 秒。业务、成员或本机实际剩余
期限可能更短。用户取消、退出或注销仍按原流程停止恢复和平台资源。

## 数据库升级与排错

此实现增加 SQLite **schema 51**，持久化新路径与原始路径的授权关系。旧 schema-50
Store 必须拒绝打开较新数据库；不能调低 `user_version`、删除祖先表或忽略拒绝
来启动旧服务端。线上部署先停止真实服务 owner，再按
[兼容与回滚说明](COMPATIBILITY-AND-ROLLBACK.md)使用原显式加密备份与迁移流程。
存在旧安装目录或旧备份本身不构成绕过准入边界的回滚授权。

恢复失败时，依次核对两端版本、同一作用域、成员凭据、业务许可和原授权剩余时间；
再检查管理员是否撤销了初始路径或其任何恢复祖先。新路径的查询会验证全部祖先，
所以撤销初始路径也会终止已恢复的连接。故障后的旧输入或画面继续不可使用。

实现和证据边界见 [ADR 0080](../adr/network/0080-signed-direct-generation-recovery.md)
及 [原生 owner 审阅](NATIVE-OWNER-AUDIT.md)。托管结果按实际源码 SHA、workflow、
job、run、attempt 和原始日志登记；全部旧失败状态和原有计时门槛继续保留。
