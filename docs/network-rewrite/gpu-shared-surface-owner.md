# Original decoder and desktop presentation ownership

The current daemon owns the real HEVC hardware decoder. Its sealed execution receipt shares the original worker's revocation and checked-join state. Desktop compressed presentation runs a separate MF/D3D owner. A UUID, the TLS client's Prepared/Decoded/Stopped message, or a syntactically valid hardware announcement cannot convert that owner into the daemon's original execution receipt.

The smallest intended shared-surface path keeps the original decoder in the daemon and lets the desktop present its decoded resources. This retains the current native channel owner, execution registry, format ACK and NLMF renewal fence. It needs all of the following:

1. Bind the mutually authenticated local TLS session to a verified destination process handle. The implemented Windows native transport reuses the original protected Tokio pipe and runs the same pinned TLS over it. It obtains the peer PID from `GetNamedPipeClientProcessId`/`GetNamedPipeServerProcessId`, retains the original `OpenProcess` handle, and checks the original TokenUser SID, desktop session and TokenStatistics authentication LUID. A PID supplied in JSON is insufficient. `VerifiedLocalPeer::export_target` now derives a private export capability from that same retained process object, with query/synchronization/handle-duplication rights. It never reopens a caller-supplied PID.
2. On the original codec worker, allocate a finite DXGI NT-handle texture ring on the exact frozen adapter. Validate every original output against its sealed format, generation and resource identity before copying that actual output into a ring slot. Export only read/presentation access to the verified peer process, with explicit handle ownership and close behavior.
3. Use the native keyed mutex/fence on both sides. Input transfer or a client acknowledgement cannot release a slot that the original GPU synchronization state does not show as consumed. Bound outstanding slots, bytes and age. A slow or abandoned consumer must stop receiving output and must not authorize replacing an unjoined owner.
4. The desktop imports the exact native texture on the same adapter and presents it through the existing native child surface. It must enforce current local authority and output deadlines; format/layout changes, logout, device loss and shutdown retire both import and export resources. Its presentation receipt remains distinct from the original decoder's execution receipt.
5. Preserve same-source hosted build provenance and separately gather physical GPU evidence for creation, import, actual fence consumption, presentation, multiple adapters, device loss, cadence and checked cleanup. A hosted parser or ledger test does not establish those facts.

The implemented first part now binds the actual pixel export path to a finite original-owner ledger. Every authenticated pixel stream admits one in-flight frame, at most 64 MiB, and the existing five-second transfer ceiling. It validates the actual decoded pixel hash against the private original execution receipt once, retains that same live fence across every asynchronous output chunk, and checks exact context, owner generation, format digest, sequence and PTS. Interrupted or invalid transfer retires the export stream. A changed execution/context requires a fresh authenticated consumer. The ledger's completion records only transferred bytes; it has no Presented state, GPU handle, caller-provided execution UUID or receipt deserializer.

This closes the gap between the receiver's pre-export receipt check and the later asynchronous IPC chunks. It does not create a DXGI shared surface or transfer a decoder. HEVC compressed-owner takeover is explicitly rejected even when the original execution is temporarily absent, so reordering preparation cannot turn a plain IPC acknowledgement into execution authority.

Windows `LocalServer::bind` retains the existing TCP listener and endpoint schema, and also accepts the native pipe for its exact runtime. New Windows clients prefer that native transport and fall back to the original TCP TLS only when no pipe exists. Access, authentication, busy or timeout errors never cause fallback. Old clients and Linux retain the TCP entry. TCP sessions have no process proof. `VerifiedLocalPeer` has no public PID constructor or serde path; it is available only after the TLS and runtime Hello checks, checks original process liveness, and shares cancellation, partial-frame failure, daemon stop, duplex-owner drop and pipe lifetime fencing. Native process tests exercise a real separate child, its original process handle after exit, frame cancellation/drop and both compatibility directions. The same-source Windows 27 tests and Linux 24 tests plus both strict checks passed on source `6cf496f`; `evidence/native-peer-process-6cf496f.json` preserves their exact limits. That run predates the later export capability and native ring.

The original HEVC worker now has an explicit shared-output command which allocates three exact NV12 NT-handle/keyed-mutex slots on its existing adapter, capped at 128 MiB total and five seconds per output. Each copy uses the actual original MF/D3D output, a bounded real GPU completion query, fresh native resource identities and a checked sequence. The original decoded receipt seals that exact private surface lease along with its pixel output. An unexported lease may be discarded locally on the original worker; once descriptor writing begins, uncertain transfer cannot take that path. Only the actual keyed-mutex return key releases an exported slot. Original peer revocation also gates execution receipts and NLMF renewal. This producer slice still requires its own hosted compilation and physical GPU execution.

The TLS surface-descriptor lane and desktop native import/presentation are the remaining implementation steps; the ordinary product route therefore still uses original hardware decode with readback presentation. Physical allocation/import/consumption, adapter/device-loss behavior and cadence have not been accepted. Production issuance stays disabled, physical GPU and advanced-format acceptance remain open, and the Luanti 25-second failure and its threshold remain preserved.
