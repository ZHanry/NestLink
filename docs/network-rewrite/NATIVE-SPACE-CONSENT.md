# Native space consent through the account actor

The desktop Spaces page now manages the existing account-scoped spaces and prepares a native path for the currently selected, mutually approved remote request. It owns no SDK, signing key, network scheduler or second account session. The generic local network page retains STUN, private-prefix and PCP consent, shows existing space consent, and offers an explicit clear operation.

The user must enter a space authority key verified through an independent trusted channel. Reading the space directory never fills or installs that key. Preview checks the selected space revision and policy epoch, the original remote request and connection generation, and the device's current verified permit. It calls the frozen `prepare_network_remote` owner for that exact business pair; an ordinary member cannot request unrelated peers or use the global policy or general peer-grant directory. The controller and host installation IDs, membership epochs, roles, permit digest, original deadline and local settings revision are shown before confirmation.

The actor retains the nonserializable `VerifiedRemotePreparation`, original permit and signed relay discovery. Public preview fields are observations, not transferable authorization. Relays are projected only from the existing permit-bound `discover_relay_nodes` response. Its original five-second budget begins before the request and is never restarted by displaying or confirming the preview. Selected node IDs must belong to that retained signed list, remain live, and be distinct.

Confirmation consumes the actor's preview once, including on failure. The authenticated IPC connection supplies the existing daemon runtime identity; the command body cannot select a different daemon instance. This follows the original local-service owner and does not create independent principals for multiple UI windows authenticated as the same local user. Confirmation checks runtime, account/login through the SDK owner, generation, local selection, nonce and original permit digest, then performs the exact preparation GET through `check_current`. It cannot mint replacement membership grants, replace the permit or renew a deadline. The original local `configure_native_network` owner performs the generation and `native_network_revision` comparison, idle checks and persistence before publishing the saved choice.

The actor uses its own monotonic selection counter in addition to the caller's context UUID. Reusing an earlier context string cannot revive an old response. Changing space, requesting another preview, inspecting/changing the remote request, logging out, switching server, or reaching the original preview deadline drops the private preview owner. Password/login generation fences continue to clear public account state and sensitive invitation slots.

Saved preparation settings contain only the original request/generation/permit digest, space revision, policy epoch and expiry, alongside the existing explicitly approved pin, pair IDs and optional node order. Native direct and routed startup recover that exact pair through `network_remote_preparation` GET and compare all saved bindings. They never issue a new preparation to repair stale saved settings. Existing legacy manually pinned settings retain their previous administrative checks for compatibility; the desktop no longer requests manual membership-grant or relay UUID entry. The original direct/route establishment, media consent, network monitor, path deadlines, revocation and recovery owners remain in use.

Invitation management reuses the existing bounded sensitive slot, zeroizing `Secret`, authenticated transient IPC and masked input field. Issued tokens are absent from snapshots, operations and events, are consumable once, and disappear on selection/login changes or after the desktop leaves the page. Copying a link is an explicit local action and does not send it to another person.

## Verification source and status

`crates/app-core/tests/spaces.rs` and `tests/spaces/native_path.rs` use the real HTTP server, database, SDK, account actor and private file store. They cover invitation one-use/target-account/role restrictions, minimal guest visibility, stale revisions, context reuse and late responses, slot clearing, bounded pagination, wrong keys/runtimes, one-use confirmation, local CAS interference, membership revocation before exact readback, account changes, persisted exact settings and an actual native direct connection involving an ordinary non-admin member. The existing native recovery and settings tests remain applicable to compatibility, persistence failure and idle cleanup.

No build, formatter, automated source check, test or native connection has been run in the local workspace. Under R02 these new cases must execute in GitHub Actions against the committed source. This document records implementation and intended checks, not passed evidence. Relay deployment, hardware, public-NAT and mobile target acceptance remain separate original gates.
