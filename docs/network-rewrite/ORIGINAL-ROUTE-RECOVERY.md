# 原始双节点组的原生远控安全恢复

当前候选实现允许原生远控在原来的中继完全断开后，从已授权的两个节点中选择仍可用的节点，完成新的设备证明并恢复会话。默认关闭。双方都必须显式配置相同的部署、空间、签名权威、控制方/被控方成员凭据和节点顺序。

当前路径授权固定最多 **30 秒**，并且只能恢复一次；实际期限还受业务许可、成员凭据和节点发现期限约束。轮询或切换不会延长期限。到期或恢复后的路径再次失败时，需要重新发起并批准新会话。这一候选功能的源码与自动化证据不代表全部 W14、AC21、AC22、AC23 或真实设备验收已经完成。

## 配置前准备

管理员先通过现有空间和节点管理入口创建空间、加入双方设备、签发当前成员凭据，并部署两个已注册且在线的原生中继。业务审批仍须独立允许远控权限和 relay 路径。成员资格本身不授予输入或屏幕访问权限。

从可信管理入口取得以下字段，核对部署与签名权威的公钥；不能仅凭节点 URI 设置信任。

| 字段 | 含义 |
| --- | --- |
| `deployment_id` | 当前管理部署的 UUID |
| `space_id` | 双方共同空间的 UUID |
| `authority_key` | 该空间签名权威的完整 32 字节公钥；JSON 使用 32 个 0–255 整数的数组 |
| `controller_membership_grant_id` | 当前控制方设备的成员凭据 UUID |
| `host_membership_grant_id` | 当前被控方设备的成员凭据 UUID |
| `node_ids` | 两个不同节点的 UUID 数组；第一个用于初始连接，第二个用于备用准备 |

控制方与被控方的角色以及节点顺序必须在双方配置中一致。这份配置针对这一对设备的角色；交换控制与被控角色时重新核对凭据。节点位于私有地址时，还须通过已有本地网络设置单独批准相应地址前缀。此模式与手动指定单个 relay、PCP 配置互斥。

## 桌面端

在没有活动原生会话时打开本地原生网络设置，勾选原始双节点组恢复，填入上表字段。桌面公钥输入框使用无填充 base64url，保存后由既有设置存储保留。按界面提示重新确认本地网络授权，然后在另一设备填写相同字段。

按正常流程发起远控并由被控方批准。路径故障时，原会话任务先停止旧连接、释放按下的按键、清理旧媒体和平台资源，再完成新代次的设备与业务认证。恢复后，被控方必须重新选择共享屏幕；旧屏幕选择、输入绑定、解码画面和待发送数据不会作为新授权继续使用。新媒体从新的关键帧开始。

取消勾选并保存即可停止对未来会话启用此配置。修改设置时，既有空闲限制和本地确认仍生效。

## 无图形 daemon

将上表字段保存为私有 JSON 文件，`authority_key` 必须是完整的字节数组，`node_ids` 必须恰有两个元素。文件须满足已有私有配置读取要求：Linux 仅当前用户可读写；Windows 使用仅当前用户及必要系统身份可访问的 ACL。配置文件最大 8192 字节。

启动参数增加：

```text
--native-route-set /absolute/path/native-route-set.json
```

该显式参数校验后保存本地同意设置。以后启动省略参数会继续保留已经保存的配置。要明确清除，启动时增加：

```text
--disable-native-route-set
```

这两个参数不能同时提供。路径和信任错误会使本次启动或连接失败；节点证书公钥不匹配、成员凭据失效、业务撤销、原始组撤销和期限届满均不会自动放宽权限。

## 排错与证据

先核对双方角色、空间、公钥、成员凭据及节点顺序，再查看当前节点资源和业务授权。管理面提交成功与节点收到新资源有很短的传播间隔；客户端只在挑战流打开之前、原有期限内处理指定的动态 TLS 准入拒绝。挑战签名和业务证明失败后不会重用已消费的分配。

实现和待验证边界见 [ADR 0033](../adr/network/0033-signed-route-set-application-recovery.md)。所有编译、格式、lint、自动测试和制品都在 GitHub Actions 执行。记录具体源码 SHA、workflow/job/run/attempt 及原始日志；真实 Windows/GPU、跨网和安装混合版本结果单独登记。
