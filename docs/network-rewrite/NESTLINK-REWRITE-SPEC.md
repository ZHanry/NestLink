## 1 开发目标和交付边界

本项目在 NestLink 现有产品之上，自主实现统一的网络连接与私有组网内核。深入研究 EasyTier 的发现、穿透、持续选路、去中心数据传输、用户态网关和可观测性机制，将机制转化为 NestLink 自己的协议、状态机、接口、代码与产品流程。最终产品不以 EasyTier 可执行文件、Rust 核心库、FFI 或源码 Fork 作为运行内核。

最终交付必须包含本规格功能矩阵中的所有功能。分阶段表示依赖顺序；“可选 TUN”“可选离线”“可选局域网发现”等表示用户可以选择是否启用，不能用作开发时跳过功能的理由。不得将后半部分需求无限期改成远景。源代码实现、生产接线、用户界面、平台验证与现场验收分别记录状态。

自主实现范围是 NestLink 特有的节点和空间模型、连接编排、候选过滤与调度策略、路由策略、授权衔接、业务生命周期和产品集成。私有服务、网关、诊断、安装与迁移也遵守成熟组件优先原则：复用现有模块或成熟通用组件，只补齐 NestLink 特有的策略与适配。TLS、QUIC、WebRTC、ICE/STUN/TURN、WireGuard、密码学及 TCP/IP 栈继续使用经过选型审查的成熟实现；保留当前合适的 Tokio、rustls、Quinn、WebRTC 和身份依赖。“自主网络内核”不要求所有底层代码由 NestLink 自行编写。

主要产品平台保持 Windows 10/11 x64 客户端、当前稳定 Chrome/Edge/Firefox Web 客户端、Ubuntu 24.04 x64/ARM64 后端。Linux 后端增加组网节点和子网网关运行角色；这不表示恢复 Linux 图形远控客户端。手机通过标准 WireGuard 客户端接入属于本次交付；Android/iOS/macOS 原生远控客户端不自动恢复。服务与协议代码保持可移植边界。

本规格不要求与 EasyTier 私有线协议互通；标准 WireGuard 客户端互通必须实现。不把任意互联网全流量出口、商业计费系统、插件市场或多链路带宽叠加加入本次范围。已有配额和用量控制必须保留。

当前轮次交付的是开发规格和执行任务，不是软件已经实现。将本文件交给 Codex 并要求执行后，Codex 应持续完成已授权的开发工作，不能只重新生成另一份规划。

### 1.1 R01 成熟组件优先 禁止重复造轮子

所有工作包按“复用仓库已有可靠实现 → 采用维护正常且适配需求的成熟组件 → 添加薄适配层 → 仅对未被覆盖的产品差异自主实现”的顺序决策。这是全局完成条件，不只适用于密码学和网络协议。不得因为“学习 EasyTier”“统一风格”“完全自主”而重写已有成熟通用功能。

| 功能类别 | 必须采用的实现方式 |
| --- | --- |
| 异步运行时 加密 安全传输 | 复用现有合适依赖或成熟替代，不自行实现密码算法、TLS 或 QUIC 可靠传输 |
| ICE STUN TURN WireGuard | 选用成熟协议实现；自主部分限于授权、信令编排、调度和接线 |
| TUN 驱动 用户态网络栈 | 复用操作系统接口、成熟驱动/provider 和网络栈，不自行开发通用网卡驱动或 TCP/IP 栈 |
| HTTP WebSocket TLS入口 代理 DNS mDNS | 优先现有网关和成熟服务器/协议库，只增加服务权限、目标限制、命名和生命周期适配 |
| 媒体 采集 编解码 呈现 | 复用成熟库、系统 API 和硬件 SDK，自主实现协商、资源归属、调度与业务恢复 |
| 存储 配置 日志 指标 安装 更新 UI | 先复用项目已有模块及成熟组件，只补齐本项目所需流程与集成 |
| 图算法 地址计算 序列化 压缩 | 优先成熟算法库与实现；路由政策、地址分配政策和签名语义由 NestLink 定义 |

W01 形成 components.json 组件选型清单，W02 冻结首批依赖。每条记录用途、已有实现、候选来源、维护情况、平台/版本/许可证、功能匹配、安全与运维成本、选择结论及适配边界。执行时核验官方资料与实际版本；成熟度不能只由 star 数量或“能编译”判断。

只有确认现有实现和成熟候选无法满足具体必要需求时，才实现最小缺口；在 ADR 中记录候选、可复核的不满足原因、最小自研范围及维护成本。该记录是工程决策，不新增逐项用户审批流程。不能把整个通用组件重写成“适配层”。每个实现任务与最终审查都要检查此项；上游来源和许可如实保留。

### 1.2 R02 所有构建及自动化验证在 GitHub Actions 执行

项目、依赖、可行性原型、测试工具及发布制品的编译、自动化检查、测试和打包均在 GitHub Actions 执行。该约束从第一个原型开始生效，覆盖全部阶段，不限于正式版本或最终回归。

| 操作 | 执行位置与要求 |
| --- | --- |
| 阅读源码 文件检索 源码编辑 Git操作 文档维护 人工静态审阅 | 可以在 Codex 工作区进行，也可读取 Actions 日志、下载并校验制品；不启动项目编译、开发服务器或本地测试 |
| 依赖安装与解析 工具链准备 绑定/协议代码生成 | GitHub Actions；固定版本及 lock，记录生成来源 |
| 格式化检查 lint 类型检查 静态分析 | GitHub Actions；包括 cargo fmt/check/clippy 及前端对应工具 |
| debug/release 原型 测试程序 前端/WASM 跨平台编译 | GitHub Actions；包括 cargo build/run、前端构建及其隐式构建步骤 |
| 单元 属性 状态机 集成 协议 网络实验 bench fuzz | GitHub Actions 中执行可自动化部分，保存日志与失败样本 |
| 镜像 安装包 压缩发行包 签名 校验摘要 SBOM 制品生成 | GitHub Actions；目标机器只接收该流程产物 |
| Windows/GPU 手机 真实NAT 跨网与长稳现场验收 | 运行从 GitHub 下载并核验的制品及验收工具；现场不安装编译工具链、不从源码构建 |

构建使用 GitHub 托管 runner。不得把用户电脑、Codex 工作区或部署服务器注册成 self-hosted runner 以绕过上述位置约束。需要特定 GPU、手机或网络拓扑的现场步骤可由 Actions 编排，或由现场人员运行已发布的验收制品；这是运行验收，不是把编译转移到现场。

Codex 的迭代方式固定为：编辑源码与工作流 → 提交/推送已授权开发分支 → 触发或等待相应 Actions → 读取该 SHA 的检查、测试和制品 → 修复并再次提交。不能先本地 cargo check/test 或前端 build，再补一次 CI。安装依赖或运行脚本若隐式触发编译，也属于禁止的本地构建。

格式化工具也在 Actions 执行；需要修改源码格式时由 Actions 输出 diff/patch，Codex 可在工作区审阅并应用。真实设备性能测量只能运行 Actions 生成的测量程序，不能在现场运行 cargo bench、cargo run 或带隐式编译的源码原型。

每个验证结果绑定源码 SHA、workflow、job、run ID/attempt、runner、依赖锁摘要和制品 SHA256。缺少 runner、执行权限、额度或外部环境时，修复可修复的工作流并继续源码工作；无法执行的项目如实待验证，不能降级成本地构建或填写成功。

上述约束针对 NestLink 项目及其开发验证流程；本开发交接文档的文本编辑、JSON 数据整理和文档压缩包制作属于文档维护。

## 2 当前代码基线和必须继承的能力

NestLink 已有真实 LAN/IPv6/STUN 候选、原生 QUIC/WSS 路径、浏览器 WebRTC/ICE/TURN、原生恢复、逐通道许可、媒体优先级、HTTP/HTTPS/TCP/UDP 服务发布和安装构建体系。重构不能把这些全部当成尚不存在的功能。

| 基线事实 | 核验位置 | 重构约束 |
| --- | --- | --- |
| 原生候选使用真实网卡与同 socket STUN | crates/sdk/src/discovery.rs 和 crates/transport-quic/src/discovery.rs | 保留映射所属 socket 及网络代次 |
| 控制端拨号 被控端主要接收入站或连接中继 | crates/sdk/src/native.rs | 新增真实双方协同检查，不能仅增加 STUN 地址 |
| 建连时竞速 首成功结束 为 WSS 留并发预算 | crates/connectivity/src/lib.rs | 增加持续优化，保留 UDP 黑洞下的回退机会 |
| 原生恢复已接入应用核心 | crates/app-core/src/runtime/native_recovery.rs | 复用清理与恢复；停止和撤销不能复活 |
| path 和 connection_generation 绑定会话证明 | crates/session/src/lib.rs | 新路径迁移需要显式协议协商，不能暗改 v15 语义 |
| 输入和反馈优先于文件 音频使用数据报 | crates/remote/src/quic.rs | 不退化为单个无界可靠队列 |
| 服务承载直接依赖 Quinn | crates/transport-quic/src/service.rs 和 crates/sdk/src/services/publication.rs | 将服务承载纳入统一适配层 |
| 服务转发内核支持通用异步流 | crates/node/src/service_plane/stream.rs | 保留业务授权内核，收敛外层具体传输依赖 |
| 公网 Web 服务拥有独立 Caddy DNS TLS 准入 | docs/refactor/SERVICE-WEB-DEPLOYMENT.md | 私网可达不能替代公网入口治理 |
| 实际媒体 socket 可绑定物理网卡 | crates/platform-network/src/path.rs | 物理承载与私网路由显式适配，避免路由回环 |

执行前核验当前工作树和上述基线的差异。当前代码优先于已经过时的历史范围说明，但代码存在不代表现场验收通过。最新产品平台范围以 config/product-scope.json 为基线，并通过新范围文档清楚登记本次新增的 TUN、空间和网关能力。

保留 docs/refactor/REMEDIATION-ACCEPTANCE.md 的既有性能、原网络、权限和发布门禁。现有定向回归通过只证明对应旧源码和制品，不能直接计入新内核验收。

## 3 如何深入学习 EasyTier 并形成自己的实现

研究固定两个来源：正式版 v2.6.4 对应 8428a89d2dabc94c97d370ec607c6ca142473626；开发分支研究快照 c66076b8f3ec16e3fff20b0df920ebda1652e04c。执行时验证这些 Git 对象；主分支的新模块和浏览器适配不能写成正式版已有能力。

按以下主题研究，每项必须输出“用户问题、输入输出、状态与资源、成功过程、失败过程、取舍、NestLink 行为用例”七项，不能只列函数名。

| 主题 | 研究问题 | NestLink 独立产出 |
| --- | --- | --- |
| 节点发现与入网 | 如何找到第一个节点 多入口如何收敛 何时使用缓存 | 发现来源模型 有效期及权限过滤 |
| NAT 与 socket 生命周期 | 双方如何协同 同 socket 如何移交 失败如何重试 | 原生连通性状态机 预算 取消和反例 |
| 拓扑与路由 | 跳数与延迟如何权衡 怎样防环和防抖 | 签名通告格式 路由策略 状态转换 |
| 中继与隔离 | 中继可见什么 谁可转发 如何防止跨空间滥用 | TransitGrant 转发封装 配额与生命周期 |
| 身份与凭据 | 成员身份和单设备身份怎样区分 撤销怎样传播 | 设备绑定成员证书 业务许可独立校验 |
| 用户态网关 | 无 TUN 如何访问 TCP/UDP 子网冲突怎样处理 | 本地代理 子网映射与受控服务出口 |
| 管理与诊断 | 配置意图与实际状态如何区分 动态配置失败如何处理 | 版本化配置事务 真实路径和错误模型 |
| 可移植核心 | 纯策略与系统 socket 路由 DNS 如何分离 | 单一网络内核 owner 与 HostAdapter |
| 浏览器边界 | 浏览器可以使用哪些协议 与原生有什么差异 | WebRTC 适配与私有 Web 网关 |

研究先形成行为说明和独立验收用例，再设计 NestLink 的数据模型与实现。保留 source-manifest.json，区分 idea_reference、standard_reference、runtime_dependency、vendored_dependency、adapted_code。不能复制、逐段翻译 EasyTier 源码或测试后改名，也不能删除其许可信息再声称 Apache 原创实现。

阅读上游源码后由同一 Codex 或共享上下文代理实现，不构成严格 clean room，本项目不作这种声明。若未来确需采用上游代码，必须如实登记来源并按对应许可证处理，不能静默混入自主实现。EasyTier 根代码许可为 LGPL-3.0；文档站页脚不是代码许可。

每个架构决定记录至少两个方案、选择理由、影响接口、失败条件、迁移方式和待测假设。研究是开发的前置工作，不允许演变为无限阅读；冻结首个可运行切片的契约后进入实现。

每个机制同时检索当前仓库及成熟组件能否复用，并记录在 components.json。学习机制不等于重写对应协议或基础设施；原型与选型验证全部按 R02 在 GitHub Actions 执行。

## 4 目标架构

采用应用连接、私有网络和接入网关三层。默认远控和单服务访问不需要 TUN；完整系统透明组网由用户启用。浏览器继续使用浏览器支持的传输，不要求安装虚拟网卡或使用实验性 WASM 特性。

~~~mermaid
flowchart TD
    UI["Windows 与 Web 工作台"] --> CONTROL["账号 设备 空间与授权"]
    CONTROL --> APP["远控与服务业务"]
    APP --> CORE["自主网络内核"]
    CORE --> PATH["发现 穿透 路由与恢复"]
    CORE --> TRANSPORT["QUIC TLS WSS 适配"]
    APP --> WEBRTC["浏览器 WebRTC 与 TURN"]
    CORE --> OVERLAY["名称 TUN 与子网"]
    APP --> GATEWAY["公网 Web 与 WireGuard 网关"]
~~~

### 4.1 模块归属

优先扩展既有 crate；确需新增的模块保持单一职责。以下是职责建议，具体目录在 W02 通过 ADR 固定，不能同时存在两套互相竞争的生产调度器。

| 模块 | 建议位置 | 职责 |
| --- | --- | --- |
| 网络协议与能力 | crates/protocol | SpaceId PeerId 候选 通告 PathGrant 诊断和协议版本 |
| 身份与权限 | crates/identity crates/policy crates/session | 成员凭据 业务许可 转发及子网授权 离线租约 |
| 统一网络内核 | 扩展 crates/connectivity 或新增 crates/network-core | 唯一 PeerManager PathManager RouteManager 和事件源 |
| 承载和连通性适配 | 现有 transport-* traversal platform-network | 库接口 socket 所有权 STUN ICE 系统网络事件 |
| 私有网络 | crates/network-overlay 或现有 node 的独立模块 | IPAM DNS TUN 本地端口代理 子网映射 |
| 网关 | 现有 node/server 的独立模块 | 公网入口 私有 Web 入口 WireGuard portal |
| 产品编排 | sdk app-core daemon desktop web | 请求批准 配置事务 恢复 UI 和诊断 |

纯策略层不能直接创建系统 socket、修改路由、写 DNS、启动进程或持有全局配置单例。通过 HostAdapter 获得网络接口、socket、单调时钟、随机数、持久化和系统配置能力。系统资源有唯一 owner，取消必须最终关闭并回收，无法确认清理完成时不得报告成功。

### 4.2 必须冻结的接口契约

| 对象或操作 | 必须包含的语义 |
| --- | --- |
| connect_peer | 目标 PeerId SpaceId purpose 已验证授权 绝对截止时间 取消 |
| AuthorizedPeerConnection | 设备身份 业务许可摘要 当前路径事实 可用能力 生命周期 |
| open_stream | 通道类型 优先级 有界缓冲 截止时间 半关闭 背压 |
| send_datagram | 通道类型 包边界 有效期 最大载荷 拥塞与丢弃策略 |
| subscribe_path_events | 候选与路径代次 实际传输 下一跳 中继列表 可用性 测量时间 |
| close_and_wait | 撤销原因 停止新流 清空敏感队列 输入释放 socket 与任务收尾 |
| apply_config | 预期 revision 验证 差异 提交 回滚或明确部分失败 |

普通 Peer 连接、网络已认证连接和业务已授权连接必须是不同类型。不存在“拿到虚拟 IP 即可绕过权限”的公共接口。不支持的能力必须明确拒绝，不能保留配置后假装生效。

## 5 身份 空间和授权

安装实例身份继续沿用现有模型。PeerId 绑定设备公钥，显示名称可改但不决定身份。SpaceId 是隔离的私有网络；同一安装可加入多个空间，成员、地址、DNS、路由、配额和日志视图按空间隔离。

使用短期签名成员证书将设备、公钥、空间、角色、有效期和策略 epoch 绑定。成员邀请是有范围、有效期、一次性消费和撤销能力的凭据；产品提供复制邀请链接或二维码，不把永久网络主密码发送给所有人。设备重装和被撤销后重入必须形成新的有效身份关系。

五组权限独立存在：

1. MembershipGrant 允许加入空间及获取受限发现信息。
2. ConnectivityGrant 与 PathGrant 允许特定设备对为特定目的建立哪些路径。
3. SessionPermit 与 ServiceLease 继续限制屏幕 输入 音频 文件 剪贴板和服务。
4. TransitGrant 与 RouteExportGrant 允许节点转发或导出明确子网。
5. NetworkAccessGrant 限制原始 IP 数据面的来源身份、获准源地址或导出前缀、目的、方向、协议/端口、期限和额度；空间成员资格不能代替此项许可。

空间角色采用 owner、admin、member、guest；真正的资源准入由设备或成员到具体服务、协议、端口、操作及期限的规则决定。默认拒绝跨成员任意端口访问。owner/admin 管理权不自动授予远控输入或本机目标批准。

账号、双方设备、本地策略、空间、服务、会话和路径许可取交集。撤销具有单调版本和签名；旧快照、晚到消息、重新连接和升级都不能恢复已撤销权限。换钥必须通过旧身份或已授权管理员明确确认，不能按同名设备替换。

## 6 发现和 NAT 穿透

候选来源包括本机接口、同 socket STUN、IPv6、明确启用的局域网发现、控制面签名目录、已认证节点提供的有效信息与自建 bootstrap。候选声明只提供可能的地址，不授予拨号权。继续执行现有本地私网范围批准和危险地址拒绝。

原生必须实现双方对候选对的协同连通性检查，包括角色冲突、事务绑定、peer reflexive 候选、检查节流、选中候选和新网络代次。优先评估成熟 ICE/STUN 实现，NestLink 自主实现权限过滤、信令、策略和承载接线。

W09 的前置原型必须证明：检查成功后仍由相同 UDP socket 或成熟库支持的同一数据报接口承载 QUIC。禁止在 socket A 打洞成功后切到 socket B 再宣称穿透完成。读取 UDP 的 owner 必须唯一，STUN 和 QUIC 分流不能抢包或留下取消后的读取任务。

先竞争 LAN/历史有效路径、IPv6 和常规 NAT UDP。允许的中继及时参与；保留独立回退预算，UDP 黑洞不能耗尽 TCP/WSS 的机会。第一条合法路径立即进入业务握手，背景优化不阻塞首屏。TLS、身份、授权失败不能被当作普通网络错误降级绕过。

必须覆盖 TCP 协同连接、有限对称 NAT 探测和可选端口映射。各操作只能面向已经认证的对端及合法候选，明确速率、并发、端口集合和总时间预算，不随机扫描公网。UPnP/NAT-PMP/PCP 类端口映射由管理员和本机用户明确启用，保存映射归属和租期，失败或关闭时清理自己的映射。并非所有部署都提供这些协议，产品必须清楚显示当前适用性。

NAT 类型用于诊断，不用来证明直连一定成功。高级穿透失败不应损坏中继路径。IPv6 临时地址、多网卡、Clash TUN、企业 VPN、DNS变化、睡眠和 Wi-Fi 漫游需要实际事件处理。

## 7 持续选路 多中继和有界多跳

区分 CarrierPath 与 PeerRoute。前者是相邻节点间的一条承载连接；后者是到目标 Peer 的端到端路线，可以直达或经过获准转发节点。业务使用稳定 PeerId，物理地址可以变化。

先过滤权限和当前有效性，再按用途选择路径。交互流重视 RTT、抖动和短队列；视频考虑可持续速率与丢包；文件优先吞吐并向交互让路；费用、配额和允许中继范围是约束。测量过期就标记未知，不能当作零延迟。

连接复用必须满足空间、双方身份及路径授权集合兼容。至少按 SpaceId、PeerPair 和兼容 PathGrant 策略建立传输组，不兼容业务使用独立端到端连接。一个普通 QUIC 连接采用一条主路线，不假设具备逐流多路径调度；组内以流优先级和带宽预算区分业务。direct_only 远控与允许 relay 的文件业务不能因复用连接而一起切到中继。每设备对的连接组数量有明确上限。

先交付多个自建 relay 的一跳主备和故障切换，再交付有界多跳。终端默认不为其他设备转发。路由通告绑定空间、签发者、boot incarnation、序号、期限和可导出前缀；验证成员身份及发布权后才参与计算。对过期通告、重放、撤销、分区、恢复、环路和冲突有明确行为。第三方声明的链路质量不能替代本机测量。

采用成熟图算法，独立实现策略和生命周期。通告有大小/频率上限、增量合并和去重；转发有 hop limit、包长、并发、队列和计费限制。按需为活跃设备建立捷径，避免所有设备永久 N² 连接。

以下是本规格建议初值，不是当前实测性能。Codex 可根据实验调整工程参数并记录 ADR，不得降低既有报告验收门槛：

| 参数 | 建议初值及约束 |
| --- | --- |
| 活跃目标路径 | 一条主路径 最多一条热备；其它候选有界低频探测 |
| 优化防抖 | 质量改善约 15% 且持续 2 秒后优化，切换后冷却 10 秒；故障切换不等待冷却 |
| 多跳 | 默认最多两个应用转发节点；更高值需独立容量与安全验证 |

| 高级端口探测 | 默认关闭；建议每会话最多 64 个明确候选端口 64 包每秒 3 秒 |

## 8 数据面和端到端安全

主方案复用 Quinn/rustls 的端到端身份和安全传输，使用自主的可路由数据报适配层承载不透明 QUIC 包。现有 transport-quic/virtual_udp.rs 是审查与适配起点。中继执行路由、资源和转发授权，不解密远控或私有服务的端到端业务载荷。

原生直达 UDP、授权 UDP 中继、多跳承载以及受限网络中的 TLS/WSS 都可以成为路由承载。可靠字节流回退必须保留包边界，设置队列、截止时间和背压，并明确报告 TCP 队头阻塞的代价。不得默认叠加 KCP、QUIC 与 WSS 多套可靠重传。可研究成熟 KCP/额外传输作为经基准验证后的策略选项，但不把协议数量作为验收指标。

端到端 QUIC 提供可靠流和 DATAGRAM；IP 包、原生数据报和控制消息按能力映射。禁止另造任意字节流的重放可靠层。代理、TUN 和服务入口的最大载荷、MTU发现、分片重组数量与寿命必须有界；不能靠无限缓冲掩盖 PMTU 黑洞。

W07 冻结物理 PMTU、每层封装开销、内层 QUIC 最大数据报、外层 DATAGRAM 载荷和 TUN MTU 的独立预算；W09 在实际打洞承载上验证。内层必须能传递合法的至少 1200 字节 QUIC 初始数据报，不能将外层 1200 字节载荷扣掉头部后直接当作内层上限。无法单包容纳时，在经过认证的承载适配层进行有界分片重组，或拒绝该路径；不依赖 IP 隐式分片。IPv6 TUN 必须提供至少 1280 字节链路 MTU，并验证完整包实际通过，必要时在隧道层分片。小包 ping 成功不能抵扣上述验证。依据为 RFC 9000 第14节及 RFC 8200 第5节。

QUIC 每连接认证仍使用设备证书和当前空间关系，业务流再次验证许可。认证失败、重放、跨空间注入、已失效业务代次、伪造路由和超额开流都需要拒绝证据。自建中继有固定可验证身份，连接到未知中继不能自动获得信任。

外层路由头的 SpaceId、目标 Peer、传输组、route ID、hop limit 与有效转发许可必须绑定。中继先校验认证邻接和转发准入，再向已授权下一跳发包，不能成为任意地址反射器。W02 冻结认证和绑定方式，复用成熟安全通道及签名库；内层 QUIC 加密不能被当作外层头已自动认证。

按媒体截止时间、通道优先级和业务语义丢弃数据，在端点加密前执行。不透明 relay 无法识别内层 QUIC stream 或某个 frame；它只按已授权传输组调度并控制额度、队列驻留和背压，不能假定可以从加密包中选择性删去视频而保留文件。

TUN 到对端节点之间可以端到端加密，但子网网关到真实 LAN 服务是另一段链路。公网 HTTPS 经 edge 终止，以及浏览器 Web 网关终止，也必须按实际加密边界描述，不能统一宣传为浏览器到任意后端的同一条端到端加密。

## 9 会话保持和路径迁移

区分安装身份 epoch、策略 epoch、应用 session generation、候选 network generation 和 path epoch。接口变化不自动扩大业务权限；业务终止不能由路径恢复撤销。

旧 v15 对端维持旧的停止、重新证明与恢复语义。新协议通过独立兼容版本或显式 path-migration-v1 能力协商，签署允许的路径集合、迁移约束与会话期限。公开版本号不能代替线协议协商。

~~~mermaid
stateDiagram-v2
    [*] --> Discovered
    Discovered --> Probing
    Probing --> Validated
    Probing --> Failed
    Validated --> Active
    Active --> Switching
    Switching --> Active
    Switching --> Recovering
    Active --> Recovering
    Recovering --> Active
    Recovering --> Closed
    Active --> Closed
    Closed --> [*]
~~~

切换必须先验证新路径，再通过认证控制通道协商 session、旧/新 path epoch、PathGrant 摘要、挑战与失效时间；双方确认后单调提交。旧路径有界排空，迟到确认不能覆盖新状态。允许的旧路径可在切换失败时继续；已撤销或过期的路径不能作为回滚目标。

正常优化优先使用既有控制通道。旧路径彻底失效时，必须能在已验证新承载上建立仅允许迁移控制的认证会话，或经管理端辅助重新证明；权限不得超过仍有效的原授权。迁移提交前不开放普通业务流。提议 ID、单调 path epoch、同时提议冲突规则、幂等确认、确认丢失与超时行为在 W02/W14 固定，不能无限等待旧路径恢复。

授权或应用代次与路径代次分别处理。已撤销、过期或被替换的业务 generation 立即拒绝；正常迁移时，前一 path epoch 在仍获准且有界的接收宽限内可交付在途包，由 QUIC 或业务序号去重。只有会话恢复创建新业务代次时，才按各通道恢复规则清除旧数据。撤销优先于任何排空宽限。

先验证当前固定 Quinn 版本的路径迁移/重绑定或虚拟 UDP 适配是否能保持同一端到端连接；不得假定某个 API 存在。除了业务连续，还要测 RTT/拥塞/PMTU 在新路径上的收敛。不具备安全保持条件时，保留应用会话标识并走既有快速恢复，不能凭隐藏传输变化宣称普遍无感。

各业务恢复语义固定：

- 视频清空过期帧，请求关键帧并重新确认显示与格式。
- 音频丢弃旧缓存，不播放断网期间积压音频。
- 输入先释放已按下按钮，不重放旧点击、按键和文本。
- 文件按原授权目录、文件标识、块校验与偏移续传。
- 剪贴板不自动重放旧写入。
- 普通 TCP 能保留就保持，不能保持时明确断开，由应用重试；不重放数据库等业务请求。
- UDP 丢弃已经失效的业务代次或超过业务期限的数据；正常 path epoch 重叠按上述宽限处理，映射和接收窗口有界。

用户明确退出、撤销、到期或身份错误是终态。正常网络恢复不自动延长许可。恢复期间 UI 显示恢复中，不能继续显示可交互在线。

## 10 私有服务 网络空间和名称访问

服务定义增加独立访问模式：private、public、both。启用 private 不自动打开公网入口；启用 public 不自动给所有空间成员访问本机。两种模式分别授权和记录用量，但共同计入既有账号、设备、节点和资源的累计总预算；同时启用不能获得两份完整额度。跨入口预留和结算必须防止重复消费。

私有服务目录支持创建、修改、停用、查询可达性和一键访问 HTTP/HTTPS/TCP/UDP 服务。服务 owner 在本机批准精确目标；用户可授权成员或设备访问指定服务。NAS、SSH、RDP、数据库及开发服务的入口提供可操作说明；普通浏览器不原生运行任意 TCP/UDP 协议。

Windows 工作台支持打开私有 HTTP 服务、建立临时本地端口映射、复制明确客户端参数和启停代理。Web 工作台显示相同权限和状态；需要本机客户端的操作给出实际前置条件，不能显示虚假的浏览器直连。

IPAM 按空间和设备分配稳定虚拟地址，支持 IPv4/IPv6 地址类型、保留、冲突检测、撤销与重新分配。重装新设备不静默继承旧身份。多空间同地址和本地路由重叠必须显式隔离、重新分配或拒绝，不能依赖最后写入的路由获胜。

名称映射绑定设备或服务身份，不能用名称取得信任。默认使用专用私有命名域，示例 nas.home.nestlink.internal，实际后缀在 W19 的兼容性测试中冻结。只为受管后缀设置 split DNS，不覆盖无关系统 DNS，不使用 .local 冒充 mDNS。重名、改名、离线、撤销、缓存过期、跨空间查询和退出清理均有测试。

## 11 无 TUN TUN 子网和 WireGuard

### 11.1 无 TUN

必须提供本机 TCP/UDP 端口映射及受限 SOCKS5。默认绑定回环；本机访问也需受凭据或本机访问控制边界保护。代理只到获准空间内的设备、服务和子网，不成为任意互联网出口。UDP 映射保留报文边界、空包、期限和配额，超大包行为明确。

### 11.2 可选 TUN

Windows 和 Linux 节点提供受管虚拟网卡模式。虚拟网卡 provider、签名、版本、许可证与分发方式经过依赖审查。普通业务进程不因此永久提升权限；权限代理只暴露创建/删除受管网卡、配置受管路由和 DNS 的最小接口。

记录本产品创建的网卡、地址、路由和 DNS 归属。崩溃、服务停止、升级回滚、卸载和部分失败都能恢复或清理自己的配置，不覆盖其他 VPN 和用户手动配置。物理 Peer 端点流量必须防止再次进入自己的 TUN 造成递归。

解密后的每个入站 IP 包，在写入操作系统或转发 LAN 前，先把认证 PeerId/SpaceId 映射到获准源地址或 RouteExport 前缀，拒绝源地址伪造，再执行 NetworkAccessGrant 的目的、方向、协议/端口、期限和配额检查。网络成员不能因此访问目标机器的任意监听端口。IPv4 分片、IPv6 扩展头和分片采用有界且统一的解析或重组策略，不能因看不到端口就跳过 ACL。返回流量只由有界连接跟踪及原授权放行，不自动开放反向任意访问。

### 11.3 子网与网对网

节点可以发布经本机与管理员批准的精确 CIDR 或单 IP。提供子网访问和双侧网对网，支持重叠 IPv4 网段映射以及 IPv6 前缀边界。目标网段、来源身份、协议/端口、方向、期限和配额进入授权。

同一前缀多网关采用明确主备；故障后新流可以切换，已有依赖网关 NAT 状态的连接不保证存续。拒绝无权限的路由发布、默认路由劫持、跨空间流量和网关反射。局域网最后一段是否加密如实说明。

未安装 NestLink 的 LAN 设备以“网关身份＋获准来源前缀”表示，并在网关及接收端执行源地址反欺骗。不能宣称这些设备各有独立 NestLink 公钥身份；需要逐设备密钥授权时应安装客户端或使用独立 WireGuard 凭据。

### 11.4 WireGuard 接入

提供标准 WireGuard portal，集成成熟实现，不重新编写密码协议。每个接入客户端有独立密钥、虚拟地址、身份映射、服务/子网范围、到期和撤销。提供配置导出及二维码；私钥不进入日志，配置作为敏感材料管理。

Android 和 iOS 各至少一台真实手机，使用官方或兼容 WireGuard 客户端实际验证私有服务与子网访问。客户端身份从独立公钥绑定关系得出，不能仅信其包内源 IP，也不能继承整个 portal 的权限。流量经过 portal，不宣传成手机自动成为完整 Mesh 节点。密钥轮换、门户故障、恢复、撤销及配额都必须实际运行。

## 12 公网服务 浏览器入口和高可用

现有 HTTP/HTTPS/TCP/UDP 发布、本机精确目标批准、来源 ACL、独立后端 TLS、配额、短租约和撤销持续保留。不要因为已有 Mesh 就删除 edge/Caddy。新增服务承载的备用路径时仍执行原业务准入。

私有 Web 网关向获准用户提供 HTTP/HTTPS/WebSocket 访问。网关绑定指定服务，禁止任意 URL 代理、任意重定向目的和 SSRF。每个不受信服务使用隔离 origin，不能将私有应用 HTML 放到管理工作台同 origin；处理 cookies、Host、Origin、CSP、CSRF、WebSocket、上传下载和登出撤销。浏览器非 HTTP 协议使用本机映射或专门协议网关，不能声称 Web 页面具有通用 TUN/UDP。

公网高可用明确区分三个层次：

1. host 到 edge 的多路径，由网络内核负责。
2. 同一服务发布到多个获准 edge，签名 ServiceLease 与 namespace revision 明确绑定入口组。
3. 外部访客访问固定地址，由受支持的公网负载均衡/VIP 或 DNS 故障切换部署方案负责。

至少交付一种在 Ubuntu 后端可重复部署验证的双 edge 固定入口方案及运行手册；可采用用户提供的负载均衡/VIP，但不能把配置文档写成已经运行的 HA。DNS-only 模式要说明 TTL、缓存与新连接恢复的边界。多入口证书、DNS 所有权、就绪探测、撤销和额度分配是独立工作，不能用 Mesh 路由切换抵扣。

HA 默认承诺新连接可恢复，已有 HTTP 长连接、TCP 或 UDP 会话在 edge 丢失时可能中断。没有复制连接状态时，不宣传已有任意会话零中断。多 edge 使用互不重叠的预留额度或一致的共享准入，不能分别领取全额造成双倍配额。

固定入口故障测试覆盖 HTTP、HTTPS、TCP、UDP 四协议。停止与撤销要检查两个 edge、旧 edge 恢复及 Caddy 入口删除确认；本机 Stopped 状态不是全入口已撤回的证据。失联 edge 最迟按既有有效租约停止，恢复后先同步撤销和 namespace 代次，不得恢复旧发布。

## 13 有限离线与异地局域网应用

### 13.1 有限离线

默认严格模式保持当前租约语义：控制面失联不延长许可，到期停止。新增管理员及本机明确启用的有限离线模式，以事先签发的 OfflineLease 授权固定设备关系与服务；原协议许可不能直接改长。

离线准入采用完整 OfflineGrantBundle：独立签名并绑定双方设备、公钥、空间、成员关系、直连路径范围、具体远控或服务操作、资源预留额度、最高已知撤销 epoch 和统一失效时间。该凭据包为每一项必需在线准入提供明确的离线替代；证书有效性和离线信任锚验证规则同时冻结。不能只签业务票据，就把已过期的成员、连接或节点资源许可视为继续有效。

本期离线模式固定支持预授权受信设备之间的直连远控和私有服务，可在该范围内恢复或重建直连。依赖 relay/transit、TURN、子网网关、WireGuard portal 或公网 edge 的访问不由此获得离线续期；这些角色继续遵守各自原有效租约。界面明确显示“离线仅直连”及当前是否具备可用直连。今后若扩展离线转发，必须额外定义节点资源、TransitGrant 和额度的完整独立离线授权，不能静默扩大本期语义。

建议初始离线有效期上限 30 分钟，属于新设计参数。界面列出允许的具体操作和失效时间。可允许预授权受信设备的远控或私有服务，但输入、文件写入等高权限必须单独批准；不能通过“允许离线”一键扩大原权限。

离线期间禁止新成员入网、权限扩大、新公网发布、新子网导出和新的管理员操作。仍即时响应本机停止和已收到的有效撤销。未收到的中心撤销无法立即生效，最坏窗口由 OfflineLease 上限决定；用户设置必须明确这一点。

使用签发时间与单调时钟锚点、防回滚状态和最高撤销 epoch。默认进程或设备重启后离线租约失效，除非另有可验证防回滚机制。离线额度先预留、持久记账；旧备份、重启或换入口不能重置配额。

### 13.2 异地局域网应用

交付受控联机空间、UDP 广播转发和指定服务的 mDNS/DNS-SD 代理。仅在明确加入的空间内开放，限制端口、来源、速率、去重、TTL 和转发方向，防止广播环与跨空间泄露。退出、撤销和关闭模式立即停止转发。

至少冻结两款合法可获得的真实 LAN 游戏：一款覆盖广播或局域网发现，一款覆盖直接 IP 连接。在两处实际网络完成开房、发现或指定地址加入、持续联机、退出和撤销，记录游戏版本、时长、协议及兼容限制。指定 mDNS/DNS-SD 代理另以真实服务发现验证。不能以打印机发现、ping 或 UDP echo 代替游戏验收，也不承诺所有二层广播、组播或所有游戏均兼容。

## 14 远控媒体和并发体验

网络重构不能代替媒体工作。本次完整交付继承当前远控功能及原报告对采集、编解码、GPU 呈现、高阶格式和体验的要求，设独立工作包修复或接通剩余链路。

保留 Windows 与 Web 的画面、键鼠、音频、文件、剪贴板、多屏、受信设备、密码与本机批准。迁移时不改变默认权限。Web 继续使用浏览器 WebRTC；不要求浏览器支持 EasyTier 开发分支的 JSPI。

输入、反馈、音频、视频和文件使用有界独立队列与合适优先级。视频以期限和新鲜度为核心，文件使用剩余预算，避免发送大文件拖住鼠标。质量调节读取实际接收反馈和编码/排队状态，降码率、降帧率、必要的分辨率切换及恢复关键帧要真实接线。

GPU 采集、编码、解码和呈现边界在 Windows 实际适配器上验证。H.264 以及原报告要求的 HEVC、4:4:4、HDR/位深与高帧组合必须有精确能力协商、实际输出和回退表；不支持硬件明确报告不支持，不伪造能力。不得把 BGRA 输入、某个枚举值或合成探针等同于全链路资格。

## 15 用户界面 诊断和运维

Windows 与 Web 工作台均提供设备、空间、服务、网络、诊断和设置的连贯入口。沿用 NestLink 品牌与现有有效交互；不为重构无故重做全部 UI。

首次配置向导检查管理 HTTPS、身份、STUN、中继、TURN、公网入口和本机目标，各项按实际启用模式判断。用户选择仅直连、允许自建中继、完整私网等模式时解释具体效果。默认禁止的中继、私网范围或公网发布不能被安装升级静默开启。

同时展示 allowed_route_policy 与 observed_route。虚拟 IP 可达不等于真实直连。显示承载协议、获知的转发节点、延迟/抖动/丢包、限速、MTU、切换原因和最近更新时间。未知外层 VPN/代理路径标记未知，不能用密码学术语承诺互联网中不存在隐藏转发。

事件以 request/session/path epoch 关联，包含发现、批准、就绪、首路径、首帧、恢复、撤销和清理。区分配置保存、主机批准、通道建立和服务真正可用。日志默认不记录密码、令牌、TURN 凭据、文件内容或屏幕内容；导出包有明确脱敏规则。

新旧配置使用版本化事务和比较更新。实例启动失败、端口冲突、缺权限、驱动缺失、网关离线和不支持能力都给出可操作错误。监控和诊断不能依赖数据通道仍然存活，失败后仍能导出最近记录。

## 16 迁移 回滚和交付构建

按 strangler 方式渐进替换：先将真实 legacy 后端接入新接口作为行为对照，再引入自主内核。新旧后端按设备/空间/部署能力协商，在受限灰度范围切换；不按请求失败自动绕过授权降级。

兼容矩阵覆盖旧客户端新服务器、新客户端旧服务器、新旧节点混合以及新协议对端。必须明确哪些功能不可用；不静默复用旧签名字段或假装旧端理解迁移。旧版本无法理解的签名对象不得降级解释。

数据库迁移先备份并核验；回滚不能恢复已撤销身份或清除配额债务。向前迁移和应用版本回退分开设计，旧二进制不能读取不支持的新 schema。TUN/DNS/服务与证书配置各有归属及恢复记录。

R02 适用于开发原型、debug/release、全部自动化检查、测试、构建、打包及制品生成；所有这些操作统一在 GitHub Actions 的 GitHub 托管 runner 执行。用户电脑、Codex 工作区和部署服务器不得执行源码编译或作为构建 runner，只运行从 GitHub 下载并核验的制品。CI 从同一干净 SHA 生成 Windows、Web、Linux x64/ARM64 后端、源代码、SBOM、许可证与材料包。扩展工作流路径过滤，确保新模块、配置与测试实际触发 CI。

W00 核对现有工作流、开发分支触发入口与可用 runner；W03 在早期建立新增模块的 Actions 检查、测试和原型任务，后续实现任务才使用这些入口。W34 完善全平台发行矩阵、安装与制品，不能等到 W34 才开始配置 CI。重用成熟 Actions、缓存与打包工具并固定依赖；缓存不能替代当前 SHA 的验证证据。

增加或更新虚拟网卡 provider、WireGuard 运行组件和服务角色时，安装、升级、卸载、签名披露、服务恢复和权限边界必须验证。缺少真实签名证书不伪造正式签名，不将开发候选推入生产更新通道。

## 17 验收标准和证据

### 17.1 继承的既有门槛

以下来自当前 REMEDIATION-ACCEPTANCE.md，执行时重新核验原文及适用条件；不能用本规格的新指标覆盖或降低。

| 用例 | 门槛 |
| --- | --- |
| 原外部 Edge 与 HL | 至少 100 次 至少 99 次真实直连；中继不能抵扣 |
| 已有分层对照 | 至少 200 次 UU 同期已直连样本，直连率差距不超过 2 个百分点，保留分层及置信区间 |
| 首个可交互画面 | 双方批准且就绪后 p95 不超过 3 秒；批准等待单列 |
| 原生 1080p60 | 合格硬件动态内容实际呈现至少 58fps，帧间隔 p95 不超过 25ms |
| 输入到显示 | 同条件独立测量 p50 不超过 UU 加 10ms，p95 不超过 UU 加 20ms |
| 弱网 | 1% 丢包及 20 到 5Mbps 阶跃，2 秒内降档，不持续积累过期视频 |
| 文件并发 | 输入延迟 p95 增幅不超过 10ms，无持续冻结 |
| 恢复 | 断网 漫游 睡眠 换网卡，有效授权下 p95 不超过 5 秒恢复可交互，旧代次不回流 |
| 长稳 | 多轮跨日 单次 24 小时，保留 CPU GPU 内存 队列 崩溃和累计延迟 |
| 撤销与退出 | 停止媒体和输入，无旧帧泄露 卡键或未授权恢复 |

新增验收还覆盖私有服务、空间隔离、TUN/DNS 恢复、重叠子网、WG 手机、广播应用、入口 HA、离线边界与混合版本。完整功能与用例映射见后面的自动生成附录及 NESTLINK-TASKS.json。

### 17.2 新工程目标

以下是本方案新增的设计验收目标，尚未实测。原型发现不可满足时保留失败并提出可审阅的技术调整，不能直接把阈值放宽为通过。

- 在受控环境且预授权备用路径健康时，断开活动中继后网络可用恢复 p95 不超过 3 秒；实际可交互恢复仍满足既有 5 秒目标。
- 本地网关和目标均健康时，私有服务撤销在 2 秒内阻止新流并停止现有获撤销流；已停止资源不能被路由恢复。
- TUN 模式正常退出后 5 秒内撤回本产品的受管路由/DNS；崩溃后下一次受管服务启动完成归属核验与清理。
- 双 edge 加已部署固定入口的受控故障场景，新连接恢复不超过 30 秒；DNS-only 单独按记录的健康检测及 TTL 评估。
- 离线测试到期 1 秒内停止新准入并清理已失效通道；前提是目标进程正常调度，不宣称暂停或掉电期间执行动作。
- 100 节点、20 活跃设备对和至少 1000 服务流的实验容量测试无跨空间泄露、无无界队列或随重连持续增长的资源。

### 17.3 证据层级

L0 编译静态检查；L1 单元、属性、状态机和模糊测试；L2 生产 socket 多进程及可控网络损伤；L3 目标平台、浏览器、驱动、安装；L4 真实公网、硬件、移动客户端和跨日长稳。低层证据不能替代高层。

证据层级不改变 R02 的执行位置。L0/L1 的项目工具执行均在 Actions；L2 的可自动化网络实验也在 Actions。L2 中确实需要外部网络拓扑的步骤，以及 L3/L4 的目标设备步骤，只能运行 Actions 构建的制品与工具，并回传绑定同一 SHA 的原始证据。纯文档研究审阅可在工作区完成，但不能借 L0 标签在本地运行编译器或 lint。

每个结果必须记录：用例和任务 ID、源码 SHA、依赖 lock 摘要、CI workflow/job/run/attempt、runner、制品 SHA256、配置摘要、系统/浏览器/驱动/硬件、拓扑、测量方法、时间与时区、原始样本、失败样本、统计口径、适用限制和审阅者。敏感信息脱敏但关联可复核。纯文档研究的 CI 字段可注明不适用，不能因此豁免实现任务。

证据分开记录 build_provenance 和 execution_provenance：前者说明哪个 Actions 构建生成了制品，后者说明本次用例实际在 github_actions、device_acceptance 或人工 document_review 中执行。现场验收引用构建记录，不得因此宣称现场测量已经由 CI 执行。

真实直连来自实际候选对、socket、握手对端与已知转发记录。配置写 direct、一次 ping、UDP echo、API 返回成功或 CI 绿色均不能替代真实远控和服务验收。

## 18 Codex 执行与完成规则

执行入口为 CODEX-START.md；机器任务清单为 NESTLINK-TASKS.json。将本套材料放在仓库 docs/network-rewrite/ 下，作为新需求与追踪文件；不覆盖根 AGENTS.md，不删除旧验收记录。

每次执行按以下循环推进：核验分支和进度、选择依赖满足任务、先检查组件复用、读取相关源码、编辑实现真实闭环、提交到 GitHub Actions 进行针对具体风险的验证、读取结果并独立审阅、修复、记录证据、继续下一个任务。基础接口可以单独审阅，但不能让对应用户功能提前变成完成。R01/R02 是所有工作包与全部代理共同遵守的硬约束。

研究、基线、契约、验证工具、审查与交付任务按各自明确产物和指定证据结项；研究任务不需要先新增生产入口，才能进入后续实现。实现工作包需要真实接线，功能整体仍必须完成生产闭环。机器清单使用 kind 和对应 completion_requirements 区分这些条件。

depends_on 表示接口和实现就绪依赖。前置任务已完成实现且只欠外部现场验收时，可以推进不依赖该验收结论的下游开发；必须继续保留验证缺口。W07 包长和封装、W09 同 socket、W14 迁移等关键可行性原型需要 L2 真实承载证据，才能作为已确认的后续设计基础。不能把“外部验证以后补”用于掩盖尚未证明可实现的数据面。

允许按协议/网络、服务网关、UI、测试工具的所有权并行。共享签名与线协议类型有单一 owner，先冻结契约再分工。独立审阅必须检查生产调用链、错误分支、权限和资源生命周期，不能只看测试数量。

任务状态采用 not_started、in_progress、implemented_unverified、verified_lab、verified_target、blocked_external、released。blocked_external 另保留 implementation_status 与 verification_status，不能掩盖仍未实现的工作。feature 完成需要生产入口、权限执行、可操作 UI/CLI、失败处理、撤销清理和适用证据均成立。

验收用例可以按明确不适用的环境记录 not_applicable_with_reason，但不能因此跳过支持矩阵中的平台或必交付功能。同一用例下的全部适用子场景完成后，才将整组记为 passed。开发和验证完成以 verified_target 为依据；released 仅在实际获准并完成发布后使用，不能为了完结任务擅自发布。

不得以空 trait、固定成功、只有 UI、只有配置、只跑 loopback、忽略平台测试、修改断言、降低性能门槛或直接编辑证据状态结项。不重复跑已充分验证且没有新风险的测试来凑数量。

确需 Windows/GPU/手机/公网/DNS/签名资源时，先完成不依赖它们的实现、GitHub 候选和可运行验收脚本，集中列出具体外部前置、对应制品及最短操作。继续完成其它不受阻任务。缺资源时如实保持相应用例待验证，不编造成功，也不因此把整个项目退回到规划阶段。

本方案不自动授予生产部署、公开发布、破坏性迁移、发送邀请消息或修改仓库权限的权限。执行时遵守用户当时的实际授权和现有仓库门禁；正常已授权开发、修复和检查不逐阶段重复索要确认。
