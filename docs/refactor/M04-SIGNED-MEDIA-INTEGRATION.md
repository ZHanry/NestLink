# M04 签名格式协商接入与剩余验收

本批接入以 `414e553b0d559865df627dd808849427011afe62` 为基底，
保留生产新格式关闭状态。它不是 M04 完成声明，也没有 RC 发布资格。
完整报告门禁见 [REMEDIATION-ACCEPTANCE.md](REMEDIATION-ACCEPTANCE.md)。

## 本批行为

设备分别发布具有签名、有效期和代次的编码或解码方向公告。请求冻结双方共同
支持的精确格式集合，首次授权页显示该集合，批准签名、permit、续租和重连
均保留原范围。扩大后续能力公告不能扩大已经批准的范围。管理读取仅将完整
验证且已经过期的公告作为缺失返回，使新探针能够重新发布；签名、身份、账号
和部署验证错误仍然失败，内部签发及可用性检查仍拒绝过期记录。

本机 CPU provider 只处理一个明确指定的目标，执行实际独立编解码输出检查后
生成历史方向证据。取消和超时不能释放仍在原生调用中的线程；线程真实结束并
join 后才释放全局探针槽。默认配置不猜测目标，也不从缓存 H.264 标记推导
GPU、硬件或 HEVC 能力。开发入口为 `--native-media-target WIDTHxHEIGHT@FPS:KBPS`。

原生运行时使用显式 NLMF 格式提议与精确 ACK，格式 epoch 和摘要同时绑定显示
选择、发送、解码及 IPC 上下文。显示 ACK 允许采集编码器产生首个真实 SPS；
独立格式门在匹配 ACK 之前阻止 AU 发送。两个发送分支检查实际 AU 的格式，
CPU 执行等级来自已签名目标，不能强制另一个等级。跨通道晚到的已退休格式 AU
仅按此前确实准备过的完整身份丢弃；未知、未来或篡改身份仍然失败。

压缩视频 IPC 使用版本 2 与完整不可变格式上下文，准入在授予解码信用之前
完成。任何显示、格式或连接代次变化都退休旧票据，旧消费者必须停止并 join。

## 测试边界

默认 Session 激活及 retained 激活继续拒绝新格式。非默认
`media-runtime-test-support` 仅为固定请求和已签名 session 提供 debug 回归入口，
仍经过真实 permit、local binding、权限、租约和端点证明校验。非 debug 构建
选择该 feature 会编译失败，产品打包命令不选择它。

Windows 专用回归包含真实软件方向探针、签名 permit、双方端点证明、业务通道、
Core 显示选择、NLMF 提议、原样暂存再放行的 ACK，以及真实 H.264 AU 解码。
它验证 ACK 前无发送或像素、ACK 后精确格式确认、过时代次与恢复请求处理、
停止后的拒绝及接收线程 join。测试使用私有 fixture 装配 Core，不覆盖 HTTP
签发或 SDK 拨号。编译、Clippy 和实际测试必须由 GitHub 给出结果。

HL 上已执行的诊断绑定此前 `414e553` 制品：1920×1080、目标 60fps、8000kbps，
软件和硬件读回方向各得到 24 个解码及颜色检查输出并完成 checked close。
这是有限功能证据，不能证明持续帧率、桌面采集、扫描呈现或逐帧像素与 PTS 对应。
GPU 首次输出失败，HEVC 首个样本被语法检查拒绝；本批增加精确分类日志和解析器
回归，没有放宽其格式约束。失败现场需要使用本批 GitHub 制品继续定位。

## 开启生产前仍须完成

- 本机实际执行 owner 的 broker：独立于已关闭探针的 UUID，按真实后端、适配器、
  驱动和目标验证当前执行资源，退休、checked close 与真实线程 join 后才接管。
- 原生双端续租证明与消费驱动。目前新增显式 SDK 刷新接口，但没有原生后台
  调用链；不能将 API 存在视为长会话续租完成。
- 同源真实正向协商、owner 更替、取消、过期、撤回及旧帧隔离测试。
- HEVC、4:4:4、10bit、高帧组合与物理 GPU 整链的真实能力和回退验收。
- 最新候选的原场景远控、公网 TCP/UDP、性能矩阵和跨日长稳验收。

签发标记与默认 Session 门禁在这些条件满足前保持关闭。报告验收包、正式
版本标签与 Release 不因本批内部测试通过而自动生成。
