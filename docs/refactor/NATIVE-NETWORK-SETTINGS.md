# 原生网络发现与本机私网批准

原生连接从已核验的管理入口读取 `GET /api/v3/network/discovery`。接口要求当前登录，返回部署 ID 和管理员配置的 STUN 数字地址；SDK 同时校验部署绑定与地址范围。STUN 仅用于发现映射，不能签发会话权限或批准私网目标。

控制中心的私密 `server.toml` 可设置 `stun_servers = []`，最多四个互不重复的公网单播 `SocketAddr`，端口必须非零。IPv6 使用 `[地址]:端口`，不接受 scope、flowinfo、域名、私网、回环、链路本地或其他特殊地址。新初始化配置默认空列表，不联系内置公共服务。示例见 [control.toml](config-templates/control.toml)。应填写管理员实际部署的 STUN 监听地址，并配置相应 UDP 防火墙。

Windows 桌面端的“本机网络设置”允许关闭部署 STUN，以及明确批准本机允许拨号的 RFC1918/ULA 子网。私网列表默认空；最多 32 项，使用规范网络地址 CIDR，每行一项，例如 `192.168.20.0/24`。全网、非规范主机位、公网、回环、链路本地和 IPv4 映射 IPv6 都不能通过该设置放行。服务器响应、远端候选和远端设备均不能修改这份批准。

设置只在没有原生或浏览器连接、建立任务、清理任务或恢复任务时提交，同时校验界面看到的 Core 代次与独立的本机网络设置版本。每次成功提交都会推进设置版本；同时打开的旧页面不能覆盖新批准，即使配置值经过修改又恢复成原值。Windows 桌面 IPC 携带这两个预期版本；队列入口和 Core actor 在真正保存前分别校验。

保存前先使旧发现代次失效；私密文件完成原子替换后才发布新配置。替换前失败保留磁盘与当前有效策略；若替换已完成而目录同步失败，则发布与磁盘一致的新策略，并在界面明确提示断电持久性尚未确认，允许再次保存相同值。已创建的临时文件由操作自己的 owner 在写入或替换失败时清理。设置文件固定为平台私有目录下的 `native-network.json`，有独立进程锁、schema 和大小限制；不存在时使用默认值，损坏记录拒绝加载。账号注销不清除此设备的本地网络选择。

默认启用部署 STUN。首次会话完成许可和对端身份核验且许可允许直连时，最多等待三秒获取配置，将管理员本地指定地址和部署地址合并、去重并限制为四个。仅中继会话不会请求无关的 STUN 发现接口。SDK 对响应头和完整成功响应体使用同一个三秒预算；收到非成功状态码后立即保留其分类，不等待错误响应体，避免慢响应体将已知的 401/403/404 等硬拒绝变成可降级超时。暂时不可达、超时或网关 502/503/504 可继续使用本地地址和接口候选。身份、TLS、登录、协议、JSON 和缺失 API 等错误会终止建立过程。恢复沿用首次建立的有效配置与原预算，不重新获取更宽的地址范围。

默认动态绑定由一个端点 owner 持有 IPv4 和 IPv6 两个 UDP/QUIC socket；两族共享同一许可、序列、连接代次和期限。IPv6 socket 使用 v6-only，按地址族分别发现和竞速。显式指定监听地址或固定端口时保留所选地址族。双栈发现不替代各链路真实可达性测试。

本次代码的定向验证结果写入后续验证回执；此文描述实现边界，不是公网、真机或已安装产品验收记录。
