| 2 | 127952935678 | 管理命令第 7 组准备与 QUIC 用例在相同 DNS 准备阶段超时；其余 2 个常驻用例通过 | `ef9de333471e177072c829a273dd3668c4b1841d4f9cd2c8188aef4b2cce23ea` |

原始日志与前两次重跑请求均保留。日志证明失败发生在已注册的 `trycloudflare.com` 临时入口等待系统解析期间；没有据此证明 DNS 失败的通用根因。第三次失败后停止原样重跑。

修复仅涉及测试入口准备：

- 用独立错误类型标识系统 DNS 准备超时。只有这个类型允许重新创建临时入口，最多三次；第三次仍失败则整个用例失败。
- 每次注册等待和系统 DNS 等待均保持原来的 60 秒；准备阶段的总体上限增加到至多三次原有尝试。测试实际产品行为的时限与断言保持原样。
- 重建之前明确杀死并回收未就绪的外部进程；清理失败直接报错。
- 每次尝试使用独立日志文件。失败诊断直接写入 stderr，即使用例后来通过，完整 CI 日志仍保留原始准备失败。
- SDK 登录发生在准备成功之后。注册、进程、清理、TLS、SDK、授权及产品断言失败均不会由该准备重试器重跑。继续使用真实系统解析器、原始 SDK 的公共 PKI 校验和冻结的 cloudflared 文件；没有替代地址、信任绕过或用例跳过。

增加三个独立回归，检查三次上限、仅返回已准备成功的入口，以及普通 I/O 超时、清理和 SDK 错误立即失败。原有四个完整常驻用例全部保留，聚焦检查的精确测试名清单增至七个。

该修复不修改 UI 或产品运行代码。新的源码必须重新通过必需检查、生成同源候选，并在用户 Windows 电脑验证对应固定产物后发布。旧候选与本机结果继续准确绑定旧提交，不能继承为新提交的通过证据。真实多设备、画面键鼠、硬件、网络与长稳验收仍按既有范围记录。
