# Foundation dispatch replacement review — 2026-10-16

The isolated candidate removes `dispatch 0.2.0` from the complete locked graph by replacing its only Foundation consumer call with already locked `dispatch2 0.3.1`. The original missing notice for `dispatch 0.2.0` remains unrecovered; this change removes that supplier rather than inventing its grant. This review does not authorize a release or substitute for Apple runtime acceptance.

## Source and implementation

`crates/platform-vendor/objc2-foundation` retains all 233 original members of the published `objc2-foundation 0.2.2` archive, SHA-256 `0ee638a5da3799329310ad4cfa62fbf045d5f56e3ef5ba4149e7452dcf89d5a8`. It retains the exact archive, original normalized and source manifests, original embedded VCS record, original sources and a complete original/local hash inventory. Its original empty author declaration remains empty. The byte-identical upstream MIT grant, including `Copyright (c) Steven Sheldon`, comes from `LICENSE.txt` at the embedded `madsmtm/objc2` revision `e282618be4c3a3b9542957e0c8540e9588472ce8`; its SHA-256 is `e353f37b12aefbb9f9b29490e837cfee05d9bda70804b3562839a3285c1df1e5`. No copyright year, author or missing dispatch grant was inferred.

Only the normalized manifest and `src/thread.rs` differ from the archive. The public `dispatch` feature now enables exact `dispatch2 = "=0.3.1"`, with defaults disabled and only `std` enabled. The successor archive SHA-256 is `1e0e367e4e7da84520dedcac1901e4da967309406d1e51017ae1abfb97adbd38`. No additional supplier version is introduced.

The `run_on_main<F, R>` signature, `F: Send + FnOnce(MainThreadMarker) -> R`, `R: Send`, main-thread fast path and marker safety operations remain unchanged. The off-main branch submits the same closure through actual `DispatchQueue::main().exec_sync`. Because the successor returns unit, independently written stack-owned `Option<R>` storage transfers the result after the synchronous callback completes. A valid `None` result and an ordinary `Err` result remain ordinary values inside that storage. The final `expect` checks the synchronous API's callback-completion guarantee; it does not catch a callback panic or recover an `R` after one. No dispatch implementation was copied.

The old callback is defined as non-unwinding `extern fn`, and the successor wrapper is non-unwinding `extern "C" fn`. Both call real `dispatch_sync_f`. No `catch_unwind`, fallback value, relaxed Send bound or `'static` requirement was added to the consumer.

The fork is explicitly excluded from workspace members and remains a third-party package with its original MIT declaration. The candidate lock removes only `dispatch 0.2.0` and changes only `objc2-foundation 0.2.2` from registry to the reviewed local source, replacing that package's `dispatch` edge with `dispatch2`. All other package fields and versions, including registry `objc2-foundation 0.3.2`, remain unchanged.

## Verification

Evidence is in `artifacts/foundation-dispatch-removal-20261016/`.

- `apple-consumer-attempt01/checks.receipt.json`: actual complete Winit checks for both baseline and candidate on `aarch64-apple-darwin` and `x86_64-apple-darwin`, with locked offline resolution, real compiler argv, logs, lock comparison and unchanged source hashes. This is cross-target type checking, not Apple SDK linking or runtime acceptance.
- `public-api-attempt01/checks.receipt.json`: both variants compile on both Apple targets with seven API forms covering scalar, owned nonclone and dynamic Send values, mutable borrowed return, scoped borrowed mutation, Send-but-not-Sync `Cell`, ordinary `Result` error and the unchanged generic signature. Both variants reject Rc capture and Rc return in four expected negative checks.
- `runtime-tool-source-attempt01/SOURCE.json` and `runtime-tool-build-attempt01/BUILD.json`: actual Linux GCD built in an owned directory from pinned upstream `swift-corelibs-libdispatch` revision `ce1b4d3540427a8c8a17a3b5eb7c5749665d384e`. Its complete source files match the exact Git tree and original full license. Nothing is installed into the system or added to the product graph.
- `gcd-comparison-attempt04/checks.receipt.json`: the exact old/new consumer function bodies run against actual old/new supplier crates and real Linux GCD, using the same explicitly test-only branch-selector marker. Each variant passes nine ordinary cases, the unchanged direct fast path, direct panic propagation, returned-value destructor panic propagation on the caller, and SIGABRT for both queued callback and captured-destructor panic. The queue cases cover scalar, nested `None`, ordinary `Err`, exact capture/result destructor counts, mutable borrowed return, `Cell`, large owned data, unit and one-shot nonclone ownership.

Linux `dispatch_main` unbinds its main queue and may execute a synchronous main-queue callback inline on the worker. The test marker carries no Objective-C authority. These checks compare queue callback/return/ownership/panic outcomes and do not prove Apple physical-main-thread execution. Of four abort cases, baseline queued-callback panic reports Linux unwinder error 3; the other three explicitly report the non-unwinding C ABI panic guard. All four exit with SIGABRT. The exact cause of the one baseline diagnostic is not established. `GCD_COMPARISON_SCOPE_CORRECTION.json` corrects an unsupported conditional interpretation about unwind frames without changing any original result or log.

Earlier runtime attempts are retained: attempt01 used Rust process entry, conflicting with Linux `dispatch_main`'s `pthread_exit`; attempt02 used C entry but incorrectly required Linux callbacks to use a different executor thread; attempt03 retained an overly specific abort diagnostic assertion. A separate pure C pthread/GCD main-queue control passed. Subsequent changes corrected only test scaffolding and diagnostics, while the exact candidate consumer function stayed unchanged.
